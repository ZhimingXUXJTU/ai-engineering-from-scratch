## समस्या  समस्या परिचय

प्रारंभिक उपकरण उपयोग पूछा गयाः क्या मॉडल एक सही फ़ंक्शन कॉल की भविष्यवाणी कर सकता है? आधुनिक उपकरण उपयोग पूछता हैः क्या मॉडल श्रृंखला उपकरण 40 चरणों में, मेमोरी के साथ, आंशिक अवलोकन के साथ, उपकरण विफलताओं से वसूली के साथ, बिना भ्रम उपकरण जो मौजूद नहीं हैं?

> आधुनिक उपकरण उपयोग का प्रश्न हैः मॉडल 40 चरणों में श्रृंखलाबद्ध रूप से उपकरण का उपयोग कर सकता है, स्मृति है, व्यवहार करने योग्य भाग है, उपकरण विफलता से पुनर्प्राप्त किया जा सकता है, और यह नहीं लगता कि कोई उपकरण मौजूद है?

### उपकरण योजना

प्रत्येक प्रदाता के पास एक योजना है। वे विवरण में भिन्न होते हैं लेकिन एक ही आकार साझा करते हैंः

> प्रत्येक प्रदाता का अपना मॉडल होता है। विवरण अलग-अलग होते हैं, लेकिन संरचना समान होती हैः

```
name: string
description: string (what it does, when to use it)
input_schema: JSON Schema (properties, required, types, enums)
```

मानवयुक्त उपयोग `input_schema`सीधे. OpenAI उपयोग करता है `function.parameters`. दोनों JSON योजना स्वीकार करते हैं. विवरण लोड-बहन हैं  मॉडल सही उपकरण चुनने के लिए उन्हें पढ़ता है. खराब उपकरण विवरण गलत उपकरण के चयन विफलताओं का # 1 मूल कारण है।

>  **【类比】**工具描述就像给实习生写的"使用说明书"――模型从未见过你的工具,它唯一能依赖的就是描述――如果你写`name: get_user, description: "gets user"`, मॉडल को पता नहीं है कि आईडी या मेल बॉक्स के अनुसार है, या फिर पूरा वस्तु या केवल नाम है।**好描述包含三要素**:做什么 + 何时用 + 输入输出语义──

> ️ **【易错点】**सबसे आम आपदाः विश्वास मॉडल वापसी के पैरामीटर प्रकार`"5"`(字符串) वापस आकांक्षा`int`की योजना**后果**:आपका उपकरण फ़ंक्शन `TypeError`                                                                                                                                                                                                                                                              **一行修复**: में उपकरण निष्पादन में प्रवेश`pydantic.BaseModel.parse_obj`या जैसे कि परीक्षा, परीक्षा विफलता, पुनः संरचनात्मक त्रुटि जैसे`{"error": "expected int, got str"}`) मॉडल पुनः प्रयास करो

> मानव 直接使用 `input_schema`✿OpenAI प्रयोग `function.parameters` दोनों JSON Schema को स्वीकार करते हैं वर्णन मूल भार है मॉडल सही उपकरण का चयन करने के लिए विवरण पढ़कर वर्णन करता है खराब उपकरण विवरण है

### तर्क सत्यापन

किसी भी उपकरण कॉल पर भरोसा नहीं करें।

> किसी भी उपकरण को विश्वास मत करो।

1. **Type coercion.**मॉडल एक स्ट्रिंग "5" लौटा सकता है जहां स्कीमा int कहता है। यदि स्पष्ट है तो मजबूर करें; यदि नहीं है तो अस्वीकार करें।
   中文翻译:**类型强制转换。**模型可能返回字符串 "5" लेकिन模式要求 int── यदि कोई भेदभाव नहीं है तो इसे अनिवार्य रूप से परिवर्तित करें; अन्यथा अस्वीकार करें──
2. **Enum validation.**यदि योजना कहती है`status in {"open", "closed"}`और मॉडल उत्सर्जन `"in_progress"`, वर्णनात्मक त्रुटि के साथ अस्वीकार करें।
   中文翻译:**枚举验证。**यदि मोड निर्दिष्ट `status in {"open", "closed"}`और मॉडल आउटपुट `"in_progress"`, वर्णनात्मक त्रुटि अस्वीकार
3. **Required fields.**आवश्यक क्षेत्र गायब -> तत्काल त्रुटि अवलोकन मॉडल में वापस, एक दुर्घटना नहीं।
   中文翻译:**必填字段。**缺少必填字段 -> 立即返回错误观察给模型, बजाय दुर्घटना──
4. **Format validation.**तारीखें, ईमेल, URL  कंक्रीट पार्सर के साथ मान्य करें, रेजेक्स नहीं।
   中文翻译:**格式验证。**दिन期、邮箱、URL विशिष्ट विश्लेषक प्रयोग करते हैं, न कि वास्तविक अभिव्यक्ति

प्रत्येक सत्यापन विफलता को एक संरचित अवलोकन लौटा देना चाहिए ताकि मॉडल सही आकार के साथ पुनः प्रयास कर सके।

> प्रत्येक परीक्षण विफलता को संरचनात्मक अवलोकन पर लौटना चाहिए, ताकि मॉडल सही प्रारूप के साथ पुनः परीक्षण कर सके।
