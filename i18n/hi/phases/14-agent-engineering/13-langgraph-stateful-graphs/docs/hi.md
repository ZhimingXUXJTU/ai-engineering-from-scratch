## समस्या  समस्या परिचय

एजेंट और वर्कफ़्लो एक समस्या साझा करते हैंः जब 40 चरणों में रन 38 में विफल होता है, तो आप चरण 38 से फिर से शुरू करना चाहते हैं, फिर से शुरू नहीं करते हैं। दूसरी श्रेणी के राज्य मॉडल ऑपरेटरों को एक पुस्तकालय के आसपास पुनः हैकिंग प्रयासों को छोड़ देते हैं जो नए रन का अनुमान लगाते हैं।

> एजेंट 和工作流共享一个问题: जब 40 步运行在第38 步失败时,你想从第38 步恢复而不是从头开始――第二级状态模型让运维围绕假设全新运行库来拼重试――

LangGraph के डिजाइन उत्तरः राज्य एक प्रथम श्रेणी टाइप किया गया वस्तु है, उत्परिवर्तन स्पष्ट हैं, और हर नोड के बाद चेकपॉइंट बरकरार रहते हैं।`load_state(session_id)`फोन करें।

> LangGraph का डिज़ाइन उत्तरः स्थिति समान नागरिक प्रकार के वस्तु है, परिवर्तन स्पष्ट है, जांच बिंदु प्रत्येक खंड के बाद स्थायीकरण है।`load_state(session_id)`

## अवधारणा का मूल अवधारणा

### ग्राफ

एक ग्राफ को परिभाषित किया जाता हैः एक टाइप किया गया डिक्ट (या पाइडान्टिक मॉडल) जो प्रत्येक नोड को पढ़ता है और उत्परिवर्तन करता है।

> 图由以下定义: एक प्रत्येक节点都读写的带类型 dict (या पिदान्टिक 模型) ⋅

- **Nodes.**शुद्ध कार्य `(state) -> state_update`. अद्यतन लौटने के बाद राज्य में विलय कर रहे हैं.
  中文翻译:**节点。**纯函数 `(state) -> state_update`更新在返回后合并到状态中──
- **Edges.**नोड्स के बीच संस्थात्मक या प्रत्यक्ष संक्रमण।
  中文翻译:**边。**节点之间的条件或直接转换――
- **Entry and exit.** `START`और `END`Sentinel नोड्स सीमा को चिह्नित करते हैं।
  中文翻译:**入口和出口。** `START`和 `END`哨兵节点标记边界──

> **【中文解读】**LangGraph का चित्र तीन तत्वों से परिभाषित हैः 1)  स्टेट प्रकार प्रत्येक节点读写的带类型 dict या Pydantic 模型; 2) 节点纯函数`(state) -> state_update`, लौट मूल्य को एक साथ स्थिति में; 3) 边节点 के बीच की स्थिति या प्रत्यक्ष परिवर्तन

उदाहरण:  के साथ एक एजेंट`classify`,`refund`,`bug`,`sales`,`done`नोड्स  एक ग्राफ के रूप में रूटिंग वर्कफ़्लो।

> उदाहरण: एक समाहित `classify``refund``bug``sales``done`节点的代理路由工作流作为图──

### टिकाऊ निष्पादन

प्रत्येक नोड लौटने के बाद, रनटाइम स्टेट को सीरियल करता है और इसे एक चेक पॉइंटर (SQLite, Postgres, Redis, कस्टम) में लिखता है। चरण N में विफलता पर, रनटाइम `resume(session_id)`और सटीक स्थिति के साथ चरण N + 1 से उठाएं।

> प्रत्येक node लौटने के बाद, runtime क्रमबद्ध स्थिति और लिखने चेक बिंदुओं में लिखें (SQLite, Postgres, Redis, स्वपरिभाषित)`resume(session_id)`और चरण N+1 से सटीक स्थिति को जारी रखें।

लैंगग्राफ डॉक्स स्पष्ट रूप से उत्पादन उपयोगकर्ताओं को उजागर करते हैं जहां यह मायने रखता हैः Klarna, Uber, JP Morgan। दावा ग्राफ आकार नहीं है; यह है कि ग्राफ आकार प्लस चेकपोइंटिंग रिकवरी सस्ता बनाता है।

>  **【类比】**LangGraph का चेकपॉइंट 像游戏的"自动档档":每过一个关卡(节点) 关于自动档一次──第38关  战挂了,你不需要从第1关重打读第37关的档再打就行──生产代理 运行40 步长任务当第38步失败时,没有检查点就从头上重跑(烧代币),有检查点 直接`resume(session_id)`接着干♪

> LangGraph 文档 स्पष्ट रूप से इस बिंदु पर उत्पादन उपयोगकर्ताओं: Klarna, Uber, JP Morgan पर जोर देते हैं।

> प्रत्येक खंड का उत्पादन भाग आउटपुट हो सकता है।

### मानव-सर्प में

नोड्स के बीच स्थिति की जांच और संशोधन करें। कार्यान्वयनः एक महत्वपूर्ण नोड से पहले रुकें, मानव को सतह की स्थिति दें, संशोधन स्वीकार करें, फिर से शुरू करें। चेक पॉइंटर यह आसान बनाता है क्योंकि स्थिति पहले से ही क्रमबद्ध है।

> इस प्रकारः मुख्य बिंदु पर पहले रोकें, मानव प्रदर्शन स्थिति को स्वीकार करें, सुधार करें, पुनर्स्थापित करें।

### जहां यह पैटर्न गलत हो जाता है

- **Non-deterministic nodes.**रिज्यूमे का मानना है कि नोड इनपुट एक ही स्टेट अपडेट उत्पन्न करते हैं। यादृच्छिक बीज, वॉल-क्लॉक, बाहरी एपीआई को कैप्चर किया जाना चाहिए।

## कीवर्ड्स  शब्द खोज तालिका

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| 术语 | 通俗说法 | 实际含义 |
| State graph | "Agent as state machine" / "Agent 即状态机" | Typed state + nodes + edges + reducers / 带类型状态 + 节点 + 边 + reducer |
| Checkpointer | "Persistence backend" / "持久化后端" | Serializes state after every node; enables resume / 每个节点后序列化状态；支持恢复 |
| Reducer | "State merger" / "状态合并器" | Function that combines current state with a node's update / 将当前状态与节点更新合并的函数 |
| Conditional edge | "Branch" / "分支" | Edge chosen by a function of state / 由状态函数选择的边 |
| Subgraph | "Nested graph" / "嵌套图" | A graph used as a node inside another graph / 作为另一个图内节点使用的图 |
| Durable execution | "Resume from failure" / "从失败恢复" | Restart at the last successful node with exact state / 在最后成功节点处用精确状态重启 |
| Supervisor | "Router LLM" / "路由 LLM" | Central dispatcher for specialist subagents / 专家子 Agent 的中央分派器 |
| Swarm | "P2P agents" / "P2P Agent" | Agents hand off via shared tools; no central router / Agent 通过共享工具移交；无中央路由 |
