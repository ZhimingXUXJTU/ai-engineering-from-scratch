## सीखने के लक्ष्य

- पिपेकेट के फ्रेम आधारित पाइपलाइन का वर्णन करेंः DOWNSTREAM (स्रोत→सिंग) और UPSTREAM (नियंत्रण) ।
- कैनोनिक वॉयस पाइपलाइन चरणों का नाम दें और जो पिएपेकेट सपोर्ट्स को परिवहन करते हैं।
- लाइवकिट एजेंट्स की दो वॉयस एजेंट कक्षाएं (मल्टीमोडल एजेंट, वॉयस पाइपलाइन एजेंट) और जब प्रत्येक फिट बैठता है, समझाएं।
- 2026 उत्पादन विलंबता अपेक्षाओं का सारांश दें और वे वास्तुकला विकल्पों को कैसे चलाते हैं।

## समस्या  समस्या परिचय

वॉयस एजेंट्स टीटीएस के साथ एक टेक्स्ट लूप नहीं हैं। लटेंसी बजट क्रूर हैं (~ 600ms), आंशिक ऑडियो डिफ़ॉल्ट है, टर्न डिटेक्शन एक मॉडल है, और ट्रांसपोर्ट टेलीफोन SIP से WebRTC तक है। या तो आप फ्रेम-आधारित पाइपलाइन (पिएपेकेट) बनाते हैं या आप एक मंच (लाइवकिट) पर lean करते हैं।

> 语音 एजेंट 不是文本循环加上 TTS──延迟预算极其严苛(约600ms),部分音频是默认状态,轮次检测是一个模型,传输方式从电话SIP到WebRTC 不等──你要么构建一个基于的管道(Pipecat),要么依赖一个平台(LiveKit)──


> **【中文解读】**语音 एजेंट 需要实时处理音频流语音识别(ASR)、LLM 推理、语音合成(TTS) का विलंब प्राकृतिक वार्तालाप को बनाए रखने के लिए 300ms के भीतर होना चाहिए。Pipecat 和 LiveKit 提供构建低延迟语音 एजेंट के ढांचे और बुनियादी ढांचे──

> **{【拓展：Pipecat（开源框架）和 LiveKit（实时音频基础设施）是 2026 年语音 Agent 生...】}**Pipecat (खुला स्रोत ढांचा) और LiveKit (实时音频基础设施) 2026 साल का है।

## अवधारणा का मूल अवधारणा

### पिपेकेट (pipecat-ai/pipecat)

- पायथन फ्रेम आधारित पाइपलाइन फ्रेमवर्क।
- `Frame`→ `FrameProcessor`श्रृंखला।
- दो प्रवाह दिशाएं:
  - **DOWNSTREAM** स्रोत → सिंक (ऑडियो में, TTS बाहर) ।
  - **UPSTREAM** प्रतिक्रिया और नियंत्रण (बदला, माप, बार्ज-इन) ।
- `PipelineTask`घटनाओं के साथ जीवन चक्र का प्रबंधन करता है (`on_pipeline_started`,`on_pipeline_finished`,`on_idle_timeout`) और मीट्रिक/ट्रैकिंग/आरटीवीआई के लिए पर्यवेक्षक।

विशिष्ट पाइपलाइनः

```
VAD (Silero) → STT → LLM (context alternates user/assistant) → TTS → transport
```

परिवहनः दैनिक, लाइवकिट, स्मॉलवेबआरटीसी ट्रांसपोर्ट, फास्टएपीआई वेबसॉकेट, व्हाट्सएप।

>  **【类比】**Pipecat के फ्रेम-आधारित पाइपलाइन 像汽车流水线:每个工位(प्रोसेसर) केवल एक काम करो  VAD 工位识别有没有人说话、STT 工位把语音转文字、LLM 工位想回复、TTS 工位把文字转语音),车架(Frame) से प्रस्थान后流过(DOWNSTREAM), किसी भी एक工位 का पता लगाने गुणवत्ता समस्या को रेडलाइन पर रोक दिया जा सकता है  UPSTREAM रद्द  यह है कि बारगे-इन 打断 तंत्र)  कुंजीः प्रत्येक工位 के बीच मानक "फ्रेम" प्रारूप                                                                                                                                                                                 

> 语音 एजेंट 结合 LLM 和实时语音处理──Pipecat 和 LiveKit दो मुख्य प्रकार के हैं 语音 एजेंट 框架,分别处理音频管道和实时通信──

पिपेकेट प्रवाह संरचित वार्तालाप (राज्य मशीन) जोड़ता है। पिपेकेट क्लाउड प्रबंधित रनटाइम है।

### लाइवकिट एजेंट (livekit/agents)

- वेबआरटीसी के माध्यम से उपयोगकर्ताओं को एआई मॉडल को जोड़ता है।
- मुख्य अवधारणाएँ: `Agent`,`AgentSession`,`entrypoint`,`AgentServer`. .
- दो आवाज एजेंट कक्षाएंः
  - **MultimodalAgent** ओपनएआई रीयलटाइम या समकक्ष के माध्यम से प्रत्यक्ष ऑडियो।
  - **VoicePipelineAgent** STT → LLM → TTS कैस्केड; पाठ स्तर का नियंत्रण देता है।
- ट्रांसफार्मर मॉडल के माध्यम से अर्थिक मोड़ का पता लगाना।
- मूल एमसीपी एकीकरण।
- SIP के माध्यम से टेलीफोन।
- लाइवकिट इन्फरेंस के माध्यम से बिना एपीआई कुंजी के 50+ मॉडल; प्लगइन्स के माध्यम से 200+ अधिक।

### जहां यह पैटर्न गलत हो जाता है

- **No barge-in handling.**उपयोगकर्ता बाधित करता है; एजेंट बात करता रहता है. पीपीकेट में यूपीएसटीआरईएम कैश रद्द करने की आवश्यकता होती है, लाइवकिट में समकक्ष।
- **STT confidence ignored.**कम आत्मविश्वास प्रतिलेखन एलएलएम के लिए दिया गया जैसे कि सुसमाचार.
- **TTS mid-sentence cutoff.**जब पाइपलाइन मध्य-उत्पादन को रद्द करती है, तो टीटीएस को ऑडियो को जानने या काटने की आवश्यकता होती है।
- **Latency budget ignored.**प्रत्येक घटक 50200ms जोड़ता है. शिपिंग से पहले अपनी श्रृंखला योग.

> **没有打断处理。**उपयोगकर्ताः एजेन्ट  Continue talking── आवश्यकता Pipecat में UPSTREAM 取消, या LiveKit में समान प्रभाव तंत्र──
> **忽略 STT 置信度。**低信度转录被当作真理传给LLM──根据信度门控或请求确认──
> **TTS 句中截断。**जब ट्यूबों में वार्तालाप के बीच में समाप्त होता है, तो टी टी एस को जानना या काटना पड़ता है।
> **忽略延迟预算。**प्रत्येक घटक 50-200ms में वृद्धि करता है।

- VAD: 2060ms
- STT आंशिकः 100250ms

## कीवर्ड्स  शब्द खोज तालिका

| Term | What people say | What it actually means |
|------|----------------|------------------------|---|
| Frame | "Event" | Typed unit of data in the pipeline (audio, transcript, text, control) |  |
| Processor | "Pipeline stage" | Handler with process(frame) |  |
| DOWNSTREAM | "Forward flow" | Source to sink: audio in, speech out |  |
| UPSTREAM | "Feedback flow" | Control: cancel, metrics, barge-in |  |
| VAD | "Voice activity detection" | Detects when user is speaking |  |
| Semantic turn detection | "Smart end-of-turn" | Model-based decision that the user is done |  |
| MultimodalAgent | "Direct audio agent" | Audio in, audio out; no text in the middle |  |
| VoicePipelineAgent | "Cascade agent" | STT + LLM + TTS; text-level control |  |
