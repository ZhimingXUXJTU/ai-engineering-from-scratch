# وكلاء متعددة الطرق واستخدام الحاسوب (كابستون) ٠

> منتج 2026 frontier هو وكيل متعدد الطرق يقرأ صور الشاشة، ويقرأ أزرار، ويتصفح واجهات الويب، ويملأ النماذج، ويكمل عمليات العمل من نهاية إلى نهاية. أظهرت SeeClick وCogAgent (2024) البدائية في إرسال واجهة التضمين. إضافة الهاتف المحمول أدى ChartAgent إلى استخدام أدوات بصرية للخطط. VisualWebArena و AgentVista (2026) هي المعايير التي يطاردها الحدود  وحتى Gemini 3 Pro و Claude Opus 4.7 نسبة ~ 30% على المهام الصعبة من AgentVista. هذه الحجر النهائي يجذب كل خيط من المرحلة 12: الإدراك (VLM عالية الصلة) ، والحكمة (LLM مع استخدام الأدوات) ، والأرض (خروج التنسيقية) ، والذاكرة طويلة الأفق، والتقييم.

> **【中文解读】**2026 عام المنتج الأمامي هو قادر على قراءة المقاطع، نقاط التدقيق، توجيه صفحات الإنترنت، ملء الملفات، والانتهاء من نهاية إلى نهاية لإنجاز تدفق العمل.

>  **【类比】**多模态 وكيل = "AI 实习生"。看截图(感知) + 想"下一步该点哪里"(推理) + 输出点击点击坐标(行动) + 看新页面(观察) + 循环。普通 VLM = 看图说话(وصف); وكيل VLM = 看图做事(执行动作)。困难在于:坐标精度(点错按) 长程规划(10步订票流程) 错误恢复(弹窗、广告、登录页) ・・・
> ️ **【易错点】**让代理 直接执行动作不设人工审核 = 灾难(可能误转账、错删除) 修复:所有"破坏性动作" ((点击提交、确认、删除按) يجب أن يكون الإنسانية الاختبار أو الجافة-القيام 模式。 فلسفة تصميم استخدام الكمبيوتر الأنثروپية هي" اقتراح→批准人类→执行",对应阶段 15·15 اقتراح-ثم-التزام 模式。

### فقط لقطة الشاشة مقابل شجرة الوصول

> **【中文解读】**两种输入模式: 纯截图模式最普遍但精度较低;无障碍树(DOM/iOS 无障碍信息) أكثر موثوقية ولكن فقط في وجود البيانات البنية المتاحة; 混合模式同时使用两者,树用于原子动作定位,截图用于语义理解;;生产代理 尽可能使用混合模式;;

وضعين إدخال:

> 两种输入模式:

- فقط لقطة الشاشة: صورة كاملة، لا توجد معلومات هيكلية. الأكثر عامة؛ يعمل على أي تطبيق.
  中文翻译:纯截图:图像完整,无结构信息──最通用;适用于任何应用──
- شجرة الوصول: معلومات الوصول المهيكلة DOM / iOS. أكثر موثوقية بكثير للتأريخ. يعمل حيث تكون الشجرة متاحة.
  中文翻译:无障碍树:结构化 DOM / iOS 无障碍信息──定位更可靠;在有树数据时可用──
- الهجائر: كلاهما، مع الشجرة كمنشأ موثوق للأفعال الذرية والصور الشاشة للسياق المفروض.
  中文翻译:混合:两者都用,树用于原子动作定位,截图用于语义理解。

## شروط رئيسية

| Term | What people say | What it actually means | 中文释义 |
|------|-----------------|------------------------|----------|
| GUI grounding | "Click coordinates" | Model outputs (x,y) for the target of an instruction on a screenshot | GUI 定位：模型输出截图上指令目标的 (x,y) 坐标 |
| Action schema | "Tool definitions" | JSON description of valid actions (click, type, scroll, drag) | 动作模式：有效动作的 JSON 描述 |
| Accessibility tree | "Structured DOM" | Machine-readable UI hierarchy from browser/iOS APIs | 无障碍树：来自浏览器/iOS API 的机器可读 UI 层级 |
| Hybrid agent | "Screenshot + tree" | Uses both image and structured info; more reliable than either alone | 混合 Agent：同时使用图像和结构化信息 |
| Visual tool use | "Zoom/crop/detect" | Agent calls external vision tools (OCR, detection) mid-plan | 视觉工具使用：Agent 在规划中调用外部视觉工具 |
| Summary-chain | "Memory compression" | Periodic text summaries replace long screenshot history | 摘要链：定期文本摘要替代长截图历史 |
| VisualWebArena | "E2E web bench" | 2024 benchmark for end-to-end web tasks | 端到端网页任务基准（2024） |
| AgentVista | "2026 hard bench" | 12-domain realistic workflows; even Gemini 3 Pro scores ~30% | 12 领域真实工作流基准，前沿模型仅约 30% |
