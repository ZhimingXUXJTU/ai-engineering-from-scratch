## مشكلة إدخال مشكلة

وكيلك يحتاج إلى الاتصال بعامل آخر في نظام آخر. كيف؟ يمكنك كشف نقطة نهاية HTTP، وتعريف مخطط JSON مخصص، وتأمل الجانب الآخر يتحدث ذلك. كل زوج من العاملين يصبح دمج مخصص.

> وكيلك 需要调用另一系统的代理──怎么做? يمكنك أن تكشف نقطة HTTP 端点، وتحدد نموذج JSON 定制، وتتمنى أن يتفهم ذلك الآخر── كل وكيل أصبح تركيبًا مخصصًا──

مشكلة تكامل N- مربع: مع وكلاء N، تحتاج N × 1) 2) / 2 تكاملات مخصصة. مع 10 وكلاء، وهذا هو 45 تكاملات. مع 100 وكلاء، 4950. A2A ينهار هذا إلى N وكلاء بطاقات، كل وصف وكيل واحد.

> N 平方集成问题:N 个代理 需要 N×(N-1)/2 个定制集成──10 个代理 是 45 个集成──100 个代理 是 4950 个──A2A 将其缩小为 N 个代理卡片,每个描述一个代理──

A2A هو بروتوكول الأسلاك العالمي لهذا المكالمة. اكتشاف قياسي، نموذج مهمة قياسي، النقل القياسي، الأثاث القياسي. مثل HTTP+REST ولكن للعملاء كمواطنين من الدرجة الأولى.

> A2A هو الاتفاق العام المستخدم للاتفاقية. المعيار التعرف على المهام المحددة. النموذج المحدد للاتصالات المحددة.

الاختصار الرئيسي: الوكلاء هي نقاط نهاية الشبكة يمكن إدراجها والاكتشاف. لا "ستستورد" وكيل؛ "تدعوه". هذا يزيل التنفيذ  يعمل وكيل أينما كان، في أي لغة، باستخدام أي إطار، طالما يتحدث A2A.

> 关键抽象:الوكيل هو قابل الوصول إلى النقطة التالية. أنت لا "导入" الوكيل. أنت "调用" ذلك.

### الانقسام بين MCP/A2A

- **MCP**(درس 13): الوكيل <-> أداة. الوكيل يقرأ / يكتب عبر JSON-RPC إلى خادم الأداة. بدون حالة افتراضية.
  中文翻译:**MCP**(درس 13): العميل <-> 工具── العميل 通过 JSON-RPC 读写工具服务器──默认无状态──
- **A2A**: العميل <-> العميل. بروتوكول الأقران؛ كلا الجانبين هم العملاء مع التفكير الخاص بهم.
  中文翻译:**A2A**وكيل: وكيل: وكيل: اتفاقات أخرى، كلتا الجانبين لديه وكيل ذاته.

تستخدم أنظمة الإنتاج متعددة الوكلاء كلاهما. يطلق أقر A2A أدوات MCP على جانبه. يحتفظ الانقسام بالاهتمامات المختلفة.

> منتجات متعددة وكالة  النظام كلتا تستخدم. A2A على الطرف الآخر في وضعها MCP  الوسائل. هذا الانفصال حافظ على وضوح نقطتين الاهتمام.

نمط شائع: "وكيل البحث" A2A في الشركة A يدعو خادم أداة البحث MCP داخليا، ثم يعيد نتائجه إلى "وكيل التحليل" A2A في الشركة B. الاتصال عبر الأورغ هو A2A؛ استخدام الأداة الداخلية هو MCP. كل بروتوكول يفعل ما هو أفضل في.

> 常见模式: A2A "مُحَلِّلُ الدّراسة" في الشركة A يُدَعِي MCP 搜索工具服务器، ثمّ سيُجدُ عُودته إلى A2A "مُحَلّلُ التحليل" في الشركة B.

### A2A مقابل ACP، ANP، NLIP

ظهرت العديد من المواصفات ذات الصلة في 2024-2026:

> بين 2024-2026 ، ظهرت العديد من القواعد ذات الصلة:

- **NLIP**(بروتوكول تفاعل اللغة الطبيعية ECMA، الموحد ديسمبر 2025)  نوع محتوى اللغة الطبيعية.
  中文翻译:**NLIP**(إيكما الطبيعي اللغة الاتفاقية، 2025)  الطبيعي اللغة نوع محتوى

A2A هو بروتوكول الأقران الأكثر اعتمادًا اعتبارًا من أبريل 2026. انظر arXiv:2505.02279 (Liu et al., "مراجعة بروتوكولات التفاعلية مع العاملين") للمقارنة.

> 截至 2026 年 4 月,A2A هي الأكثر اتساعا في التقارير المتبادلة.

## شروط الرئيسية

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| A2A | "Agent-to-agent" / "Agent 对 Agent" | Peer protocol for agents to call other agents across systems. Google 2025. / Agent 跨系统调用其他 Agent 的对等协议。Google 2025。 |
| Agent Card / Agent 卡片 | "The agent's business card" / "Agent 的名片" | JSON at `/.well-known/agent.json` describing skills, endpoints, auth. / 描述技能、端点、认证的 JSON。 |
| Task / 任务 | "The unit of work" / "工作单元" | Async stateful object with a lifecycle; artifacts produced on completion. / 具有生命周期的异步有状态对象；完成时产生工件。 |
| Artifact / 工件 | "The result" / "结果" | Typed output: text, structured JSON, image, video, audio. First-class media. / 类型化输出：文本、结构化 JSON、图像、视频、音频。一等媒体。 |
| Opaque lifecycle / 不透明生命周期 | "How it's solved is the agent's business" / "如何解决是 Agent 的事" | Client sees state transitions; server is free to choose framework/tools. / 客户端看到状态转换；服务器自由选择框架/工具。 |
| Discovery / 发现 | "Finding the agent" / "找到 Agent" | `GET /.well-known/agent.json` returns the card. / 返回卡片的 GET 请求。 |
| MCP vs A2A | "Tools vs peers" / "工具 vs 对等" | MCP: vertical agent <-> tool. A2A: horizontal agent <-> agent. / MCP：垂直 Agent <-> 工具。A2A：水平 Agent <-> Agent。 |
| ACP / ANP / NLIP | "Sibling protocols" / "兄弟协议" | Adjacent specs; A2A is the most-adopted 2026. / 相邻规范；A2A 是 2026 年采用最广泛的。 |
