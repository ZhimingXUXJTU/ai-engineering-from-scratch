# لماذا "مُعدّل العميل"؟

> عميل واحد يضرب جدار، الحركة الذكية ليست عميل أكبر، بل أكثر عملاء.

> **【中文解读】**هذا القسم يعرض لماذا تحتاج العديد من العملاء  النظام العميل  المشكلة  الفوضى والشعور بالارتباك  والكيفية التي يمكن للعملاء  من خلال التعاون التنفيذي لحل هذه المشاكل

> **【拓展：why multi agent→具体应用】** العميل الوحيد في معالجة المهام المعقدة يواجه ثلاثة عبوات:  1) 上下文溢出 كل المعلومات في نافذة واحدة ، المهمة تغرق ؛  2) اضطراب الوظيفة  عميل واحد يلعب العديد من الأدوات التي تؤدي إلى تنازلات الكلمات ؛  3) سلسلة تنفيذ أدوات تصل فقط يمكن أن تتواجد.

  中文翻译: تحليل العديد من العملاء 复杂性(延迟、成本、调试难度) مع عامل واحد 简单性

## المشكلة المشكلة المشكلة

لقد بنيت وكيل واحد في المرحلة 14، يعمل. يمكنه قراءة الملفات، تشغيل الأوامر، الاتصال بالمنصات التنفيذية، والحكم حول النتائج. ثم تقوم بتوجيهها إلى قاعدة رمزية حقيقية: 200 ملف، ثلاث لغات، اختبارات تعتمد على البنية التحتية، ومتطلب للبحث في المنصات التنفيذية الخارجية قبل كتابة الرمز.

> في المرحلة 14 ، تقوم ببناء وكيل واحد. يعمل بشكل جيد ، قادر على قراءة الملفات.

الفجوة بين وكلاء التجربة وكلاء الإنتاج هي الفجوة بين "ملف واحد، لغة واحدة، أداة واحدة" و"ملفات كثيرة، لغات كثيرة، أدوات كثيرة مع الاعتمادات". يعمل التجربة لأن المهمة تناسب. يفلح الإنتاج لأن المهمة لا.

> العرض الفرق بين وكيل وموثوق هو "وثيقة واحدة ‬ ‬ لغة واحدة ‬ أداة واحدة" والفرق بين "عدد من الملفات ‬ العديد من اللغات ‬ العديد من الأدوات المعتمدة"‬ العرض فعال لأن المهمة مناسبة‬ ‫ فشل الإنتاج لأن المهمة غير مناسبة‬

الوكيل يختنق. ليس لأن ماجستير التدريس غبي، ولكن لأن المهمة تتجاوز ما يمكن لمركز واحد حلول التعامل معه. نافذة السياق يملأ بمحتوى الملفات. الوكيل ينسى ما قرأه قبل 40 مكالمة أداة. يحاول أن يكون باحثا، ومدمج، ومراجعا في وقت واحد، و يفعل كل ثلاثة بشكل سيء.

> العميل قد انهار. ليس لأن ماجستير في العلوم الجامعية غباء، ولكن لأن المهام تتجاوز مجال العميل الواحد.

هذا هو السقف الذي يستخدم عامل واحد، تضربه كلما تطلب مهمة:

> هذا هو العميل الوحيد فوق الحد... كلما كانت المهمة تتطلب الشروط التالية سوف تواجه:

السقف هيكلي وليس خوارزمي. LLM أفضل يؤخر السقف ولكن لا يزيل. نافذة سياق 1M-الرمز يملأ تماما مثل 200k واحد  فإنه فقط يأخذ المزيد من الملفات.

> الحد الأقصى هو الهيكلي، وليس الحسابي. أفضل LLM 延迟上限但不移除它.

- **More context than fits in one window**- قراءة 50 ملف ينفجر أكثر من 200 ألف رمز
  中文翻译:**超出一个窗口容量的上下文** 读取 50 文件会超过 200k رموز
- **Different expertise at different stages**- البحث يتطلب تحفيز مختلف عن توليد الرموز
  中文翻译:**不同阶段需要不同的专业知识** البحث يحتاج إلى تكوين نصائح مختلفة عن الكود
- **Work that can happen in parallel**لماذا تقرأ ثلاث ملفات متتالية عندما يمكنك قراءتها في وقت واحد؟
  中文翻译:**可以并行执行的工作**إذا كان بإمكاننا أن نقوم بـ قراءة ثلاث وثائق في وقت واحد، لماذا يجب أن نقوم بـ قراءة؟

## المفهوم الأساسي

### السقف الذي يعمل بمُعامل واحد

وكيل واحد هو حلقة واحدة، نافذة سياق واحدة، عرض نظام واحد. تخيل ذلك:

> العامل الوحيد هو دورة واحدة فوق نافذة واحدة تحت النظام

```
┌─────────────────────────────────────────┐
│            SINGLE AGENT                 │
│                                         │
│  ┌───────────────────────────────────┐  │
│  │         Context Window            │  │
│  │                                   │  │
│  │  research notes                   │  │
│  │  + code files                     │  │
│  │  + test output                    │  │
│  │  + review feedback                │  │
│  │  + API docs                       │  │
│  │  + ...                            │  │
│  │                                   │  │
│  │  ██████████████████████ FULL ███  │  │
│  └───────────────────────────────────┘  │
│                                         │
│  One system prompt tries to cover       │
│  research + coding + review + testing   │
│                                         │
│  Result: mediocre at everything         │
└─────────────────────────────────────────┘
```

إن طلب النظام الواحد هو السبب الجذري. يجب أن يقدم تعليمات للبحث، والترميز، والمراجعة، واختبار في نفس الوقت. كل تعليمات تخفيف الآخرين. ينتهي العميل "أفضل" في كل شيء، ممتاز في أي شيء.

> 单系统提示是根本原因──它必须同时为研究,编码,审核和测试提供指令──每条指令稀释其他──代理 最终在所有事上"还行",在任何事上都不优秀──

ثلاثة أشياء تكسرها:

> ثلاثة مشاكل ستؤدي إلى انهيار:

1. **Context saturation**وبحلول الجولة الثلاثين، استهلك العميل 150 ألف رمز من محتويات الملفات، ومخرجات الأوامر، والحكمة السابقة، وتضيع التفاصيل الحرجة من الجولة الخامسة.
   中文翻译:**上下文饱和** 工具結果不断堆积──到第30轮时,Agent 已消耗150k 代币文件内容、命令输出和前推理──第5轮关键细节丢失──

2. **Role confusion**- إشارة نظامية تقول "أنت باحث، مُبرم، مراجعة، ومختبر" تنتج وكيل يبحث نصف، نصف مُبرم، ولا ينهي مراجعة.
   中文翻译:**角色混乱** إشارة النظام التي كتب فيها "أنت الباحث، المبرمج، المراجع والمختبر" ستخلق نصف البحث، نصف التعديل، وكيل المراجعة غير المكتملة للأبد.

3. **Sequential bottleneck**العميل يقرأ الملف "أ"، ثم الملف "ب"، ثم الملف "ج"، ثلاث مكالمات متسلسلة لـ"مدرسة التدريس"
   中文翻译:**串行瓶颈** وكيل 读取文件 A,然后文件 B,然后文件 C──三次串行 LLM 调用──三次串行工具执行──没有并行性──

العميل الوحيد هو عالم عام يطلب منه أن يكون متخصصا في كل خطوة.

> وكيل واحد هو واحد مطلوب في كل خطوة لتصبح متخصصة في كل خطوة.

### الحل المتعدد الوكلاء

تقسّم العمل، أعط كل عميل وظيفة واحدة، نافذة سياقية واحدة، وطلب نظام واحد مصمم لهذا العمل:

> 拆分工作── أعط كل عميل مهمة ‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬

هذا هو "فرق المخاوف" المطبقة على وكلاء LLM. استئناف كل وكيل أقصر وأكثر تركيزا. نافذة سياق كل وكيل يحمل فقط ما يحتاجه. يمكن اختبار كل وكيل وتحسين بشكل مستقل. يتعامل الموسيقي التكوين.

> هذا ينطبق على "النقاط التركيزية" للعميل LLM. كل عميل يقدم نصائح أقصر وأكثر تركيزا. كل عميل يحتوي على نافذة أعلى و أدناه فقط على ما يحتاجه. كل عميل يمكن اختبارها وتحسينها بشكل مستقل.

```
┌──────────────────────────────────────────────────────────┐
│                    ORCHESTRATOR                          │
│                                                          │
│  "Build a REST API for user management"                  │
│                                                          │
│         ┌──────────┬──────────┬──────────┐               │
│         │          │          │          │               │
│         ▼          ▼          ▼          ▼               │
│   ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐  │
│   │RESEARCHER│ │  CODER   │ │ REVIEWER │ │  TESTER  │  │
│   │          │ │          │ │          │ │          │  │
│   │ Reads    │ │ Writes   │ │ Checks   │ │ Runs     │  │
│   │ docs,    │ │ code     │ │ code     │ │ tests,   │  │
│   │ finds    │ │ based on │ │ quality, │ │ reports  │  │
│   │ patterns │ │ research │ │ finds    │ │ results  │  │
│   │          │ │ + spec   │ │ bugs     │ │          │  │
│   └─────┬────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘  │
│         │           │            │             │         │
│         └───────────┴────────────┴─────────────┘         │
│                          │                               │
│                     Merge results                        │
└──────────────────────────────────────────────────────────┘
```

كل عميل لديه:
- طلب نظام مركز ("أنت مراجع رمز. وظيفتك الوحيدة هي إيجاد الأخطاء".)
  中文翻译:一个聚焦的系统提示("أنت من قراءة الكود.
- نافذة سياقها الخاصة (غير ملوثة من عمل الوكلاء الآخرين)
  中文翻译: خليفة عمل عميل آخر
- عقد واضح للدخول/الخروج (يتلقى ملاحظات البحث، ومدونة الخروقات)
  中文翻译:清晰的输入/输出契约(接收研究笔记,输出代码)

لا يحتاج وكيل الموسيقي إلى معرفة كيفية القيام بكل مهمة فرعية. كل وكيل متخصص يحتاج فقط إلى معرفة وظيفته الضيقة. فصل المخاوف، تطبيق على LLM.

> 编排 وكيل فقط يحتاج إلى فهم مهام الارتفاع وكيفية إرسالها.

### متى لا تستخدم العاملات المتعددة

الوكيل المتعدد يضيف التعقيد. كل رسالة بين الوكلاء هي نقطة فشل محتملة. إزالة الخطأ يذهب من "قراءة محادثة واحدة" إلى "تتبع الرسائل عبر خمسة وكلاء".

> تعدد العاملين المختلفين في المجال المختلف. كل رسالة بين العاملين هي نقطة إعاقة محتملة.

**Stay single-agent when:**
- تناسب المهمة في نافذة سياق واحدة (أقل من ~ 100k رموز من البيانات العاملة)
  中文翻译:任务适合一个上下文窗口(工作数据不超过约100k代币)
- لا تحتاج إلى إشارات مختلفة للمرحلة المختلفة
  中文翻译:不同阶段不需要不同的系统提示
- الإعدام التسلسلي سريع بما فيه الكفاية
  中文翻译:顺序执行速度足够快
- المهمة بسيطة بما فيه الكفاية أن تقسيمها يضيف المزيد من التكاليف العامة من القيمة
  ترجمة: المهام بسيطة جداً، فقطة زيادة من الإنفاق أكثر من قيمتها

**The complexity cost:**
- كل حدود العميل هي خطوة ضغط ضائعة: يتم تلخيص السياق الكامل للعميل A في رسالة للعميل B
  كل عميل  الحدود كلها مصغرة خطوات: العميل A كاملة على النص التالي يتم الإجمالي لإرسال رسالة إلى العميل B
- منطق التنسيق (من يفعل ماذا، متى، في أي ترتيب) هو مصدر الخاص به من الأخطاء
  中文翻译:协调逻辑 ((谁做什么、何时做、按什么顺序) نفسها هي حشرة مصدر
- زيادة التأخير: N العاملين يعني N سلسلة LLM الدعوات الحد الأدنى، أكثر إذا كانوا بحاجة إلى التحدث ذهابا وإيابا
  中文翻译:延迟增加:N 个代理意思至少N 次串行 LLM 调用,如果需要来回对话则更多
- مضاعفات التكلفة: كل وكيل يحرق الرموز بشكل مستقل
  中文翻译: تكلفة倍增: لكل وكيل 独立消耗代币

قاعدة عامة: إذا كانت مهمة تستغرق أقل من 20 مكالمة أداة وتتناسب مع 100 ألف رمز، فبقي الأمر وكيل واحد.

>  تجربة قانون: إذا كانت مهمة تحتاج فقط لا يصل إلى 20 مرة استخدام الأدوات، ويفي 100K رمز، تبقي وكيل واحد.

```typescript
  const code = await fakeLLMCall(
    systemPrompt,
    `Given this research:\n${contextWindow.join("\n")}\n\nNow write code for: ${task}`
  );
  contextWindow.push(code.output);
  totalTokens += code.tokens;
  totalToolCalls += code.calls;

  const review = await fakeLLMCall(
    systemPrompt,
    `Given all previous context:\n${contextWindow.join("\n")}\n\nReview the code.`
  );
  contextWindow.push(review.output);
  totalTokens += review.tokens;
  totalToolCalls += review.calls;

  return {
    content: contextWindow.join("\n---\n"),
    tokensUsed: totalTokens,
    toolCalls: totalToolCalls,
  };
}
```

مشاكل هذا النهج:
- نافذة السياق تنمو مع كل مرحلة، وبحلول مرحلة المراجعة، تحتوي على ملاحظات بحثية وكود واعتبارات سابقة.
  ترجمة باللغة الصينية: على النوافذ التالية النوافذ تتزايد مع كل مرحلة.
- إن طلب النظام عام لا يمكن ضبطه لكل مرحلة
  中文翻译:系统提示是通用──不能为每个阶段调优──
- لا شيء يسير بالتوازي
  中文翻译:没有并行执行。

حلقة الوكيل الواحد تجبر ماجستير في العلوم على التبديل السياقي بين مهام معرفية مختلفة جدا (البحث مقابل التشفير مقابل المراجعة) في كل دور. كل تغيير يكلف الجودة.

> 单代理 循环迫使 LLM 每轮在非常不同的认知任务(研究 vs 编码 vs 审阅) 之间切换上下文──每次切换都损质量──

الآن تقسّمها كل عميل يحصل على وظيفة واحدة

> الآن تفصلها كل عميل يحصل على مهمة:

```typescript
type SpecialistAgent = {
  name: string;
  systemPrompt: string;

function createSpecialist(name: string, systemPrompt: string): SpecialistAgent {
  return {
    name,
    systemPrompt,

const researcher = createSpecialist(
  "researcher",

);

const coder = createSpecialist(
  "coder",
  "You are a senior TypeScript developer. Given requirements and research notes, write clean, tested code. Nothing else."
```

كل متخصص لديه طلب مركز. كل واحد يحصل على نافذة سياق نظيفة مع المدخلات التي يحتاجها فقط.

> كل خبير لديه نصيحة مركزية. كل منهم يحصل على نافذة النص الصافية، تحتوي فقط على المدخلات اللازمة.

يتم تحسين طلب الباحث للقراءة والإيجاز. يتم تحسين طلب المشفر للكتابة من الشفرة النظيفة. يتم تحسين طلب المراجع للعثور على الأخطاء. لا يوجد طلب واحد يحاول القيام بكل ثلاثة.

> نصيحة المحقق على قراءة وتحسين الإجمالي. نصيحة المحرر على كتابة تصفيحات الكود. نصيحة المراجع على اكتشاف الأخطاء.

### الخطوة الثالثة: تنسيق من خلال الرسائل

إرسال رسالة معينة إلى المتخصصين

> 通过显式消息传递将专家连接起来:

```typescript
type AgentMessage = {
  from: string;
  to: string;
  content: string;
  timestamp: number;
};

async function multiAgentApproach(task: string): Promise<AgentResult> {
  const messages: AgentMessage[] = [];
  let totalTokens = 0;
  let totalToolCalls = 0;

  const researchResult = await researcher.run(task);
  messages.push({
    from: "researcher",
    to: "coder",
    content: researchResult.content,
    timestamp: Date.now(),
  });
  totalTokens += researchResult.tokensUsed;
  totalToolCalls += researchResult.toolCalls;

  const coderInput = messages
    .filter((m) => m.to === "coder")
    .map((m) => `[From ${m.from}]: ${m.content}`)
    .join("\n");

  const codeResult = await coder.run(coderInput);
  messages.push({
    from: "coder",
    to: "reviewer",
    content: codeResult.content,
    timestamp: Date.now(),
  });
  totalTokens += codeResult.tokensUsed;
  totalToolCalls += codeResult.toolCalls;

  const reviewerInput = messages
    .filter((m) => m.to === "reviewer")
    .map((m) => `[From ${m.from}]: ${m.content}`)
    .join("\n");

  const reviewResult = await reviewer.run(reviewerInput);
  messages.push({
    from: "reviewer",
    to: "orchestrator",
    content: reviewResult.content,
    timestamp: Date.now(),
  });
  totalTokens += reviewResult.tokensUsed;
  totalToolCalls += reviewResult.toolCalls;

  return {
    content: messages.map((m) => `[${m.from} -> ${m.to}]: ${m.content}`).join("\n\n"),
    tokensUsed: totalTokens,
    toolCalls: totalToolCalls,
  };
}
```

كل وكيل يتلقى فقط الرسائل الموجزة إليه لا تلوث السياق. 50 ألف رمز من الباحث من قراءة الوثائق لا تدخل أبداً سياق المراجع.

> كل عميل فقط يتلقى رسائل لنفسه. لا يوجد أي إصدار من التلوث.

هذه هي الفوز الأساسي: عزل المعلومات. نافذة السياق لكل وكيل مكرسة لمهمتها الخاصة. ميزانية 200K توكن من وكيل واحد لا يتم إهدارها على عمل آخرين وكلاء.

> هذا هو الميزة الأساسية: انفصالات المعلومات. كل عميل يتركز على مهمته.

```typescript
async function compare() {
  const task = "Build a rate limiter middleware for an Express.js API";
```

يستخدم إصدار متعدد الوكلاء أكثر من مجموع الرموز (ثلاث وكلاء، ثلاثة مكالمات LLM منفصلة) ولكن سياق كل وكيل يبقى نظيفاً. تحسن جودة كل مرحلة لأن طلب النظام متخصص.

> عدة وكلاء  إصدار استخدام المزيد من الوهم الإجمالي  ثلاث وكلاء، ثلاث مرات مستقلة LLM 调用) ، ولكن كل وكيل على أعلى نطاق الوصول تحتفظ干净── كل مرحلة تحسن الجودة، لأن النظام تظهر متخصصة──

التجارة واضحة: إنفاق المزيد من الرموز، الحصول على إنتاج أفضل. يستحق ذلك عندما تكون المهمة صعبة. ليس يستحق ذلك "إجراء تلخيص هذه الفقرة".

> الوزن واضح جدا:花更多令牌,获得更好的输出.

## شروط الرئيسية

| Term | What people say | What it actually means |
|------|----------------|----------------------|
| Swarm / 群体 | "A hive mind of AI agents" / "AI Agent 的蜂巢思维" | A set of peer agents with shared state and no fixed leader. Behavior emerges from local interactions. / 一组具有共享状态且无固定领导者的对等 Agent。行为从局部交互中涌现。 |
| Orchestrator / 编排器 | "The boss agent" / "老板 Agent" | An agent whose tools include spawning and managing other agents. It plans and delegates but may not do the actual work. / 一个工具包括生成和管理其他 Agent 的 Agent。它规划和委派，但可能不做实际工作。 |
| Coordinator / 协调器 | "The traffic cop" / "交通警察" | A non-agent component (often just code, not an LLM) that routes messages between agents based on rules. / 一个非 Agent 组件（通常只是代码，不是 LLM），根据规则在 Agent 之间路由消息。 |
| Consensus / 共识 | "The agents agree" / "Agent 们达成一致" | A protocol where multiple agents must reach agreement before proceeding. Used when conflicting outputs need resolution. / 多个 Agent 在继续之前必须达成一致的协议。用于需要解决冲突输出的情况。 |
| Emergent behavior / 涌现行为 | "The agents figured it out themselves" / "Agent 自己想出来的" | System-level patterns that arise from agent interactions but were not explicitly programmed. Can be useful or harmful. / 从 Agent 交互中产生但未被明确编程的系统级模式。可能有用也可能有害。 |
| Fan-out / fan-in / 扇出/扇入 | "Map-reduce for agents" / "Agent 的 Map-reduce" | Splitting a task across parallel agents (fan-out), then combining their results (fan-in). / 将任务分配给并行 Agent（扇出），然后合并它们的结果（扇入）。 |
| Message passing / 消息传递 | "Agents talk to each other" / "Agent 之间互相交谈" | The communication mechanism between agents: structured data sent from one agent to another, replacing shared context windows. / Agent 之间的通信机制：从一个 Agent 发送到另一个 Agent 的结构化数据，替代共享上下文窗口。 |
