## المفهوم الأساسي

### أربعة بدائيات

سطح الطاقم صغير، تذكر هذا والباقي هو محفوف

> المواجهة المقابلة للطاقم صغيرة جدا. تذكروا هذه، الباقي هو التوظيف.

> عملة العاملين 协作建模为角色团队(أفراد) و الأحداث القيادة التدريبية(جريان)

- **Agent.** `role + goal + backstory + tools + (optional) llm`. القصة الخلفية تحمل الحمل. إنها تشكل النغمة، الحكم، عندما يتوقف الوكيل. الأدوات هي الوظائف التي يمكن للوكيل أن يدعو (أكثر أدناه).

>  **【类比】**وكيل CrewAI 定义像招聘JD(职位描述):دور هو عنوان الموقع (("资深数据分析师"),الهدف هو KPI (("بحث عن الاتجاهات الرئيسية في البيانات"),الخلفية هي enterprise culture wash brain (("أنتم خبراء متقدمين في IBM 工作 20 سنوات، ركزوا على اليقظة...") "....**关键洞察**:خلفية قصة ليست مُزينة، فإنه يؤثر حقا على تصميمات ماجستير في العلوم الجامعية  كتابة نفس الوكيل  ك" عالِم صارم" أو "مُبتكر متحفز"، 
- **Task.** `description + expected_output + agent + (optional) context + (optional) output_pydantic`وحدة عمل قابلة لإعادة الاستخدام`expected_output`هو العقد`context`يُدرج المهام التي يتم نقل نتائجها إلى الأعلى. `output_pydantic`يفرض شكل مهيكلي
- **Crew.**حاوية، يمتلك قائمة`agents`، قائمة`tasks`،`process`، و اختياري `memory`+ `verbose`+ `manager_llm`الإعدادات
- **Process.**استراتيجية التنفيذ: تسلسل، Hierarchical، Consensus (مخطط) يختار شكل الجولة.

العملاء لا يراهم بعضهم البعض مباشرة، المهام هي عملاء مرجعية، الطاقم يقوم بتسلسل المهام، العملية تقرر من يختار المهمة التالية، هذا هو النموذج العقلي بأكمله.

> العميل 之间不直接见彼此──任务 引用 العميل── عملة 排列任务序── العملية تحديد من يقوم بالقيام بالمهام التالية── هذه هي النموذج الكامل للقلوب──

> **Validated against**CrewAI 0.86 (2026-05). الإصدارات الحديثة قد تُعيد تسمية أو دمج أنواع العملية. تحقق من [CrewAI Processes docs](https://docs.crewai.com/concepts/processes)قبل الاعتماد على شكل معين

### التسلسل مقابل الهيراخرية مقابل الإجماع

- **Sequential.**المهام تتم بالترتيب الذي أعلنت به.`context`أقل تكلفة، أكثر قابلية للتنبؤ، استخدم عندما يتم تحديد الطلب.
- **Hierarchical.**وكيل مدير (مكالمة LLM منفصلة) الطرق بين المتخصصين. CrewAI يولد المدير إما من`manager_llm`إعداد أو افتراض. يختار المدير المهمة التالية في كل جولة ويمكن رفض أو إعادة توجيه. استخدم عندما يكون لديك أربعة أو أكثر من المتخصصين والطلب يعتمد حقا على الناتج السابق.
- **Consensus.**المخطط، غير تنفيذ حاليا في API العام. الأدلة تحفظ الاسم لعملية مستقبلية القائمة على التصويت. لا تعتمد عليه اليوم.

يضيف التسلسل الهرمي مكالمة LLM لكل جولة (المدير) فوق كل مكالمة متخصصة. يمكن أن تتضاعف تكلفة الوهم في رحلة خمس خطوات. دفعها فقط عندما تحتاج إلى التوجيه.

> ️ **【易错点】**انظر كروآاي  الملفات المثليين كلها باستخدام الهيركية  النموذج على اتباعها**后果**: حساب单爆炸هيراريكية كل دورة أكثر من مرة مدير LLM 调用,5 步任务变 10 مرات LLM 调用,token 成本翻 3 倍。**一行修复**:默认用序列性 (成本最低、最可预测),只有 المهام تسلسلة حقا يعتمد على الخطوة السابقة输出 (如客服分流) لتطوير إلى الهرمية。

### تكامل الأدوات

ثلاثة طرق لإعطاء العميل أداة اختر أسهل أداة تناسبك

> هناك ثلاثة طرق لتقديم الوكيل الأدوات. اختر الأسهل.

> عملة العاملين 协作建模为角色团队(أفراد) و الأحداث القيادة التدريبية(جريان)

1. **`@tool` decorator.**تصبح الوظائف النقية أدوات. التوقيع هو النظام؛ وثيقة القاعدة هو وصف LLM يرى. أفضل للمساعدين مرة واحدة.

   ```python
   from crewai.tools import tool

   @tool("Search the web")
   def search(query: str) -> str:
       """Return top results for the query."""
       return run_search(query)
   ```

2. **`BaseTool` subclass.**أداة على أساس الفئة مع مخطط args صريح، دعم التزام المزامن، محاولات إعادة. استخدم عندما يكون لدى الأداة حالة (عميل، مخزن مخزن) أو تحتاج إلى args مهيكلة.

   ```python
   from crewai.tools import BaseTool
   from pydantic import BaseModel

   class SearchArgs(BaseModel):
       query: str
       limit: int = 10

   class SearchTool(BaseTool):
       name = "web_search"
       description = "Search the web and return top results."
       args_schema = SearchArgs

       def _run(self, query: str, limit: int = 10) -> str:
           return self.client.search(query, limit=limit)
   ```

3. **Built-in toolkits.**جهاز CrewAI يُرسل مُعدّلات الطرف الأول: `SerperDevTool`،`FileReadTool`،`DirectoryReadTool`،`CodeInterpreterTool`،`RagTool`،`WebsiteSearchTool`-مُتواصلة مع إحدى الواردات

المخرجات المهيكلة تستخدم Pydantic.`output_pydantic=MyModel`على المهمة. CrewAI تؤكد استجابة LLM ضد النموذج وإما الإكراه أو محاولات إعادة.`expected_output`الخروج من النص الحر جيد للمخططات؛ الخروج المهيكلة هي ما يمكن أن تستغله التدفقات التدريبية.

> 结构化输出使用 Pydantic──在 任务 上传入 `output_pydantic=MyModel` عملة الجامعة  استجابة الجامعة الجامعية  تجربة الجامعة الجامعية  لا تتناسب  إجبارية التحول أو إعادة التجربة  تتناسب `expected_output`字符串使用──自由文本输出适合草稿;结构化输出才是下游流 可以消费的──

### مضادات الذاكرة

يُخرج جهاز CrewAI أربعة أنواع من الذاكرة من الصندوق، وهي تكوّن: يمكن للطاقم تمكين الأربعة في وقت واحد.

> المجموعة المفتوحة تُقدم أربعة أنواع من النماذج. يمكن استخدامها معاً.

> **Validated against**CrewAI 0.86 (2026-05). الإصدارات الأخيرة تسير كل شيء من خلال نظام موحد `Memory`النموذج المفاهيمي أدناه لا يزال قائماً، ولكن سطح الطبقة العامة قد ينهار إلى واحد `Memory`نقطة دخول في الإصدارات الأخيرة .[CrewAI memory docs](https://docs.crewai.com/concepts/memory)لل API الحالية.

- **Short-term.**حافز محادثة في غضون جولة واحدة تم مسحها في النهاية
- **Long-term.**استمر عبر الجرائد. مخزن في DB المتجه (Chroma من قبل الافتراض، قابل للتبادل). يتم استرداده من خلال التشابه مع المهمة الحالية.
- **Entity.**" العميل X في خطة الشركة " يُحدد من قبل الكيان وليس من خلال التشابه.
- **Contextual.**يسترد وقت التجميع، يستخرج الذاكرة ذات الصلة في اللحظة التي يحتاجها العميل، وليس قبل التحميل.

أجهز على الطاقم مع `memory=True`أو حسب النوع. مدعوم من قبل مزود التوابل التي تقوم بتكوينها (الديفالتيات إلى OpenAI ، قابل للتبادل إلى المحلي). الذاكرة هي واحدة من الأماكن التي تستحق CrewAI احتفاظها ضد الإطارات الرقيقة.

> في الطاقم على طريق`memory=True`أو حسب النوع من التكوينات لتشغيلها.

### حيث يذهب هذا النمط خطأ

- **Prompt-bloat from backstories.**قصة خلفية 2000 كلمة لكل وكيل وطاقم من خمسة عملاء تحرق ميزانية السياق قبل أول مكالمة أداة. احتفظ بالقصص الخلفية تحت 200 كلمة. استعمل عبارات عبر العملاء؛ لا تكرر نمط المنزل خمس مرات.

> **背景故事导致的提示膨胀。**كل وكيل 2000 كلمة قصة خلفية، بالإضافة إلى فريق من خمسة وكلاء، في أول أدوات تعيين، تم استهلاكها قبل استخدام الميزانية التالية. سيتم التحكم في قصة خلفية في 200 كلمة. عبر وكيل استعمال قصة قصة؛ لا تكرر خمس مرات نفس النمط التوضيح.
- **Manager-LLM token tax.**عملية الهرمية تضيف مكالمة مدير LLM قبل كل مكالمة متخصصة. على طاقم من خمسة مهام هو ستة مكالمات LLM بدلا من خمسة، والكالم مدير يحمل قائمة المهام الكاملة بالإضافة إلى المخرجات السابقة. الانتقال إلى التسلسل ما لم يعتمد التوجيه على المخرج.

> **管理者 LLM 的 Token 税。**النموذج المستوى يزيد مرة واحدة قبل كل دعوة متخصصة مدير LLM  دعوة. فريق من خمسة المهام يتحول إلى ست مرات LLM  دعوة بدلا من خمس مرات، ومدير دعوة تحمل كامل قائمة المهام加 قبل الخروج.
- **Brittle handoffs.**المهمة N `expected_output`هي "خطاط". المهمة N+1 تقرأها على أنها `context`ويحاول تحليل ثلاثة أقسام، وقدمت الهيئة أربعة، وذلك من خلال إعلانات العميل المتدفق عليها،`output_pydantic`على المهمة N لذلك المهمة N + 1 تقرأ كائنًا مكتوبًا ، وليس نصًا حرًا.

> **脆弱的交接。**المهام`expected_output`"إنه" المخطط العام.`context`读取并尝试解析三个部分──LLM 生成四个──下游 وكيل 即兴发挥──用 `output_pydantic`修复任务 N,让任务 N+1 读取类型化对象而非自由文本。
- **Crew-as-prod.**الطاقم الحر يتم شحنه إلى الإنتاج دون غلاف التدفق. تغيرات الإنتاج مرتفعة؛ لا يمكن إعادة تشغيلها؛ لا يمكن التمييز بين الجولة السيئة مقابل الجولة الجيدة. غلف مع التدفق.

> **Crew 直接上生产。**没有包装成流程 就将自由形式 Crew 发布到生产环境──输出变异性高;无法重放;值班人员无法对抗好坏运行──用流程 包装──

## الفخاخة

- **Backstory as flavor.**إنه يشكّل الخروج، اختبر ثلاثة خيارات لكل وكيل، الخيار حقيقي، اختر واحد، ثم تجمده.

> **把背景故事当装饰。**فهي في الواقع تصنع الناتج. كل وكيل يختبر ثلاثة متغيرات. الفرق حقيقي.
- **Skipping `expected_output`.**بدون عقد لكل مهمة، المهام المتدفقة تتحمل ما ينتجته الهيئة

> **跳过 `expected_output`。**没有每个任务的契约,下游任务会接收LLM 生成的任何内容──船员 运行通过;审计失败──
- **Memory always-on.**المدى الطويل يكتب كل مرة، ويتزايد الجهاز المتجه إلى النقل، ويتزايد الضجيج، ويتم إعادة التأثير، ويتم إعادة التأثير إلى المهام التي لا تزال موجودة.

> **记忆始终开启。**长期记忆每次运行都写入──向量数据库不断增长──检索变杂──将写入范围限制在需要持久化事实任务──
- **Manager prompt drift.**إن أصبح التوجيه غريبًا، فلترميه في وضع اللفظ وتقرأ

> **管理者提示漂移。**إشارة المديرين في الوضع الزمني هي خفية. إذا أصبح الطريق غريبًا، فاستخدم الفصيلة 模式导出并阅读。
- **Tool side effects in Crews.**يمكن للطاقم استدعاء أداة أكثر من المتوقع.

> **Crew 中的工具副作用。**الموظفين قد يكونوا أكثر استخداماً من المتوقع. يجب وضع عمليات التسجيل والتحميل في خطوات التدفق.

## شروط الرئيسية

| Term | What people say | What it actually means |
|------|----------------|------------------------|---|
| Agent | "Persona" | Role + goal + backstory + tools |  |
| Task | "Unit of work" | Description + expected output + assignee + optional structured output |  |
| Crew | "Agent team" | Container for Agents + Tasks + Process |  |
| Process | "Execution strategy" | Sequential / Hierarchical / Consensus (planned) |  |
| Flow | "Deterministic workflow" | Event-driven, code-owned, testable |  |
| Backstory | "Persona prompt" | Tone and judgment shaper for the Agent |  |
| `@tool` | "Function tool" | Decorator that turns a function into a tool the Agent can call |  |
| `BaseTool` | "Class tool" | Class-based tool with args schema, retries, async support |  |
| Entity memory | "Per-entity facts" | Memory scoped to a customer / account / issue |  |
| Long-term memory | "Cross-run memory" | Vector-backed memory that survives between kickoffs |  |
| Contextual memory | "Just-in-time retrieval" | Memory pulled at the moment the Agent needs it |  |
| Manager LLM | "Router agent" | Extra LLM in Hierarchical process that picks the next task |  |
| `expected_output` | "Task contract" | String that tells the Agent (and audit) what shape to return |  |
