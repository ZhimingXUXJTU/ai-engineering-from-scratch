### مخطط الأداة

كل مزود لديه مخطط. يختلفون في التفاصيل ولكنهم يشتركون في نفس الشكل:

> كل مزود لديه نموذج خاص به.

```
name: string
description: string (what it does, when to use it)
input_schema: JSON Schema (properties, required, types, enums)
```

الاستخدامات الإنسانية `input_schema`مباشرة. OpenAI يستخدم `function.parameters`. كلتا القبول JSON Schema. وصفيات تحمل الحمل  النموذج يقرأها لتحديد الأداة الصحيحة. وصف أداة سيئة هي السبب الرئيسي للفشل في أداة اختارة خاطئة.

>  **【类比】**وصف الادوات مثل "توصيف استخدام" كتبها للمدرسين.`name: get_user, description: "gets user"`، لا يعرف النموذج على الإطلاق هو حسب الهوية أو حسب البريد، العودة هي الكائن الكامل أو مجرد الاسم.**好描述包含三要素**:做什么 + 何时用 + 输入输出语义。

> ️ **【易错点】**أوائل المشكلة: النوع العادي من المعايير التي تعود إليها النوع العادي`"5"`(字符串) عودة إلى الحظ`int`من النظام**后果**: your tool function `TypeError`-تنهار، كل حلقة العميل**一行修复**: في أدوات تنفيذ الإدخال`pydantic.BaseModel.parse_obj`أو مثل تجربة، تجربة فشل عندما يعود إلى الخطأ الهيكلي`{"error": "expected int, got str"}`دع النموذج يُحاول مرة أخرى

### تأكيد الحجج

لا تثق في أي مكالمة أداة.

> لا تثق بأي أداة

1. **Type coercion.**قد يعود نموذج سلسلة "5" حيث تقول النموذج int. إجبار إذا كان غير واضح؛ رفض إذا لم يكن.
   中文翻译:**类型强制转换。**模型可能返回字符串 "5" ولكن模式要求 int。 إذا كان هناك اختلافات في الإرادة على التحول؛ وإلا فإن رفضها。
2. **Enum validation.**إذا كان النظام يقول`status in {"open", "closed"}`و نموذج الإصدارات`"in_progress"`، رفض مع خطأ تصريفي.
   中文翻译:**枚举验证。**إذا تم تحديد الموضة`status in {"open", "closed"}`و النموذج المخرج`"in_progress"`، مع تصريح الخطأ رفضها
3. **Required fields.**المجال المطلوب مفقود -> ملاحظة الخطأ الفوري العودة إلى النموذج، وليس تحطم.
   中文翻译:**必填字段。**缺少必填字段 -> 立即回归错误观察给模型,而不是崩。
4. **Format validation.**التواريخ والبريد الإلكتروني والمدونات الإلكترونية تثبت معدات الخرسانة، وليس regex.
   中文翻译:**格式验证。**يستخدم محرك تحليل محدد، وليس إعلانات رسمية.

كل فشل في التحقق من التحقق يجب أن يعيد ملاحظة مهيكلة حتى يمكن للنموذج تجربة جديدة مع الشكل الصحيح.

> كل مرة يفشل فيها التجربة يجب أن يعود إلى الملاحظة الهيكلية، حتى يتمكن النموذج من إعادة التجربة في شكل صحيح.

## أرسلها .

`outputs/skill-tool-registry.md`يخلق كتالوج أداة، مخطط، وسجل لمجال مهمة معين. يتضمن التحقق من جودة التوصيف (هل وصف كل أداة يخبر النموذج متى لاستخدامه؟)

> `outputs/skill-tool-registry.md`لقيام مهمة محددة في مجال إنتاج المعدات قائمة الأدوات والأنماط والرجسومات.

## تمارين التدريب

1. إضافة أداة "لا تشغيل" التي تسمح للنموذج رفض صراحة استخدام أي أداة أخرى. قياس على اختبار الهلوسة مثل BFCL.
   中文翻译: اضيف أداة "بدون تشغيل" ، فجعلي النموذج يرفض بوضوح استخدام أي أداة أخرى.
2. تنفيذ التجبر على الحجة من أجل الإدخال والعطف من أجل الحبل من أين يبدأ الإكراه بإخفاء الحشرات الحقيقية؟
   中文翻译:实现字符串到int 和字符串到float 参数强制转换──强制转换何时开始隐藏真实 bug?
3. إضافة وقت وقف لكل أداة ومقطع حلقة (رفض الأداة لمدة 60 سنة بعد 3 فشل متتالية). ما الذي يتغير من هذا حول كيفية التعافي من النموذج؟
   ترجمة: إضافة كل أداة فوق الوقت والقطع
4. اقرأ وصف BFCL V4. اختر فئة واحدة (مثل "معدة التحول") و إشغيل 10 مثالات من خلال وكيلك. تقرير معدل الانتقال.
   中文翻译:阅读 BFCL V4 描述──选择一个类别(如"多轮")并通过你的代理 运行 10 个示例提示──报告通过率──
5. نقل مؤكدة الـ (إستدليب) إلى (بيدانتيك) أو (زود) ما الذي أمسك به (بيدانتيك) / (زود) الذي فات له اللعبة؟
   中文翻译:将标准库验证器移植到Pydantic 或 Zod──Pydantic/Zod 捕获了玩具版本遗漏的什么?

## شروط الرئيسية

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| 术语 | 通俗说法 | 实际含义 |
| Function calling | "Tool use" / "工具使用" | Structured-output tool invocation with validated schema / 带验证模式的结构化输出工具调用 |
| Toolformer | "Self-supervised tool annotation" / "自监督工具标注" | Schick 2023 — keep tool calls whose results reduce next-token loss / Schick 2023——保留减少下一个 token 损失的工具调用 |
| BFCL | "Berkeley Function Calling Leaderboard" / "Berkeley 函数调用排行榜" | 2026 benchmark: 40% agentic, 30% multi-turn, 10% live, 10% non-live, 10% hallucination / 2026 基准：40% 智能体、30% 多轮、10% 实时、10% 非实时、10% 幻觉 |
| Tool schema | "Function signature for the model" / "模型的函数签名" | name, description, JSON Schema of arguments / 名称、描述、参数的 JSON Schema |
| tool_use_id | "Correlation ID" / "关联 ID" | Ties a tool call to its result; essential for parallel dispatch / 将工具调用与其结果关联；并行分派必需 |
| Hallucination detection | "Know when not to call" / "知道何时不调用" | V4 category: refuse to call when no tool fits / V4 类别：无合适工具时拒绝调用 |
| Argument coercion | "String-to-int repair" / "字符串到整数的修复" | Narrow fixes for predictable schema-mismatch; reject if ambiguous / 可预测模式不匹配的窄修复；如果歧义则拒绝 |
| Sandboxing | "Tool execution boundary" / "工具执行边界" | Per-tool read/write surface, network, timeout, memory cap / 每个工具的读写范围、网络、超时、内存上限 |
