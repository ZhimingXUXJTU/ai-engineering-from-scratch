## 问题背景

变压器预计一个序列. 一批是一个长度相同的序列. 如果你的图像是224x224,你每次得到196个补丁代币,不需要填充,工作完成. 列车在224,推断在224,再也不会考虑分辨率.

> 变压器 期望固定长度序列──一批就是一堆等长序列──如果图像都是224x224,每次都产生196个补丁代币,无需填充,问题解决──训练和推理都用224,永远不用考虑分辨率──

图片截图是景观 (16:9).收据是高的和薄的 (1:3).医疗成像船在2048x2048或更大.移动设备截图是1170x2532 (0.46:1).

> 现实世界不配合──文档是向的(8.5x11英寸,约 2:3)──图表截图是横向的(16:9)──收据又高又窄(1:3)──医疗影像动 2048x2048或更大──移动设备截图是1170x2532(0.46:1)──

两种2024年前的选择,

> 2024年前三项选项及其各自失败原因:

1. 缩小到固定方形 (224x224或 336x336). 鱼扭曲了文字和面孔. 低尺度破坏了图标和OCR内容.
   > 缩放为固定正方形(224x224或336x336) ――缩放会扭曲文字和人脸――下采样会破坏图表标签和OCR 内容――LLaVA-1.5 之前的标准做法――
2. 现在,我们需要一个小小的图像,
   > 剪切为固定宽高比.将丢弃大部分图像,选择剪切位置本身就是一个视觉问题.
3. 片在最长的侧面. 修复扭曲,但浪费50%以上的代币在片图像.
   > 填充到最长边缘──修复扭曲但对屏图像浪费50%+的代币 在填充上──所有填充代币的注意力成本是二次的──

> **【中文解读】**变压器 期望固定长度的序列──真世界图像宽高比不同,2024年前有三种做法: 1) 缩小为正方形文字变形、OCR 内容丢失; 2) 剪裁丢弃大量内容; 3) 填充屏图像浪费50%+的代币 在填充上,注意力计算成本第二次增长──

答案是:让变压器吃到图像原始分辨率的补丁,

> 2024-2025年答案:让变压器直接使用原始分辨率的"吃"补丁,然后想办法将不同构成的批量包装成一个序列而不浪费计算.

### 包装掩码

对于一个包装的长度序列,`N_total`覆盖图像`i=0..B-1`长度`n_i`面具`M`形状`(N_total, N_total)`如果两个指数都属于同一图像的区块,则是1.

```
offsets = [0, n_0, n_0+n_1, ..., N_total]                         # 累积偏移量
M[i, j] = 1 iff there exists b where offsets[b] <= i < offsets[b+1] # 同一图像块内为1
                        and offsets[b] <= j < offsets[b+1]
```

这是一个字符串在 PyTorch `torch.block_diag`闪电注意力的变量长度路径 (`cu_seqlens`) 完全跳过面具,并使用累积长度子直接在序列中进行处理,比典型批量密集面具快10倍.

> **【中文解读】**块对角掩盖确保每张图像的补丁只关注自己,不会"看到"其他图像的补丁.`cu_seqlens`直接用累积长度张量做注意力,跳过密集掩码,速度约快10倍.
