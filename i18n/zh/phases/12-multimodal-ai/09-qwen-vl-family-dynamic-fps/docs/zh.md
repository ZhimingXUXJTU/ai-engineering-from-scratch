## 问题背景

文-VL于2023年8月出货,作为LLaVA-1.5和BLIP-2的直接反应.文团队的目标差距是三倍:分辨率,视频和结构性输出.

解析度:LLaVA-1.5 运行于336x336. 照片很好,对于一个中文发票或密集的电子表格截图来说是无用的. 文-VL 的第一个创新是448x448和地面边界框输出,让模型指向东西.

视频:视频-LLaMA堆了每一个框架的编码器,然后将它们输送到LLM. 它适用于短片,而不是多分钟的视频,时间轴是信号.

结构化输出:LLaVA发射了自由形式文本.一个代理需要JSON.Qwen-VL训练在明确的JSON输出格式,包括边界框坐标作为文本.

每一代Qwen-VL都延伸了三个轴之一.

> **【中文解读】**对于LLaVA-1.5的三大不足发起挑战: 1) 分辨率336x336 无法处理中文发票或密集表格截图; 2) 视频视频-LLaMA只能处理短片段; 3) 结构化输出LLaVA 输出自由文本,代理需要JSON──每一代Qwen-VL都在这三个轴上延伸──

### 文-VL (八月2023年) 首代

第一代:OpenCLIP ViT-bigG/14作为编码器 (2.5B参数),LLama兼容的Q-Former (1步,含256个查询),Qwen-7B基础.贡献:

- 现在,我们可以看到一个图像,然后我们可以看到一个图像.
- 定位:训练在图文对文本对子上,有明确的坐标标输出. "猫在 <box>112,204), (280,344)</box>".
- 开始就支持中英双语训练.

当时的标准:与GPT-4V在英语上竞争,在中国上占主导地位.

> **【中文解读】**文-VL 第一代突破:448x448 分辨率(超越LLaVA的336x336) 定位能力(输出边界框坐标) 中英双语──在中文基准上显著领先──

### wen2-VL (2024年9月) M-RoPE和本土分辨率

文2-VL 取代了固分分 + Q-Former 堆,并用了原生动分辨率 ViT 编码器.

- 视频可接受任何可以28 (补丁14与2x空间合并) 分的 HxW. 图像在1120x672 (40x24合并补丁) 产生960个视觉代币.没有尺寸,没有,没有缩影.
- 对于图像 t=0,视频 t=frame_index. RoPE 每个代币都携带一个3D位置 (t, h, w) 而不是1D. RoPE每轴的频率旋转查询/关键向量.没有位置嵌入表.
- 放弃Q-Former,在合并的补丁代币上使用2层MLP.
- 动态率视频. 视频默认样本在1-2 FPS,但模型接受任意的框架计数.

结果:Qwen2-VL-7B在多个多模式基准上匹配GPT-4o,并在 DocVQA (94.5 vs 88.4) 上击败了它.

> **【中文解读】**文2-VL的核心结构变更:删除固定分辨率+Q-Former,换成原生态分辨率 ViT + M-RoPE + MLP 投影机──M-RoPE 为每个代币 赋予3D位置(时间、高度、宽度),使同一位置编码能够统一处理文本、图像和视频──7B 参数就匹配GPT-4o的多模态基准──

### 关于数学的方法

经典的ROPE旋转查询`q`尺寸`d`按位置`m`使用对联坐标:

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)   # 经典 RoPE 旋转
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)                                                 # 频率基
```

光将隐藏的暗光分为三段.`d = 96`按时间点分配32个,高度32个,宽32个.每个带按自己的轴位置旋转.一个 (t=5,h=10,w=20) 的补丁得到旋转.`R_t(5)`现在`R_h(10)`现在`R_w(20)`它们的三条带.

文字代码使用`t = text_index, h = 0, w = 0`视频片使用 视频片使用`t = frame_time, h = row, w = col`单个图像使用`t = 0`现在,我们要去.

优势:一个位置编码处理文本,图像和视频,而不需要分类代码或不同的位置表.

> **【中文解读】**M-RoPE 将隐藏维度分为三个频段 ((时间、高度、宽度),每个频段按各自轴位置旋转──文本代币 用 (text_index, 0, 0),视频用 (frame_time, row, col),单图用 (0, row, col)──好处:一套位置编码统一处理文本、图像和视频──

### 动态率采样逻辑

视频时间`T`秒和目标代币预算`B`其他:

1. 计算你能负担的最大FPS:`fps_max = B / (T * tokens_per_frame)`计算最大的率.
2. 选择一个目标FPS`{1, 2, 4, 8}`这满足了`fps <= fps_max`选民中选择.
3. 如果运动量高率,运动量小则低率.
4. 在选择的FPS均样本;插入 `<time>t</time>`时间的标志.

wen2.5VL 暗示了这种逻辑;`fps`参数:一个60秒的动作序列,4FPS,每框81个代币 =19440个代币,可在32k环境中管理.

> **【中文解读】**动态率的核心思想:根据视频时长、代币 预算和运动量,自动选择最佳率──60秒动作场景在4FPS下产生1944个代币,可在32k上下文中处理──

### 结构化代理输出

文2.5VL的代理培训明确针对结构化工具调用:

```
{
  "tool": "mouse_click",          # 工具名称
  "coords": [1024, 512],          # 点击坐标
  "button": "left",               # 鼠标按钮
  "modifier": null                # 修饰键
}
```

解析是决定性的:JSON.parse对模型的输出.比较自由形式的"点击 (1024, 512) "要求进行regex和模糊处理.这就是为什么Qwen2.5-VL的ScreenSpot分数从Qwen2-VL的55%跳到84%.

> **【中文解读】**结构化输出让VLM可以直接发出可解析的工具调用 (如点击坐标),无需正则表达式――这是ScreenSpot精度从55%跳到84%的关键原因――
