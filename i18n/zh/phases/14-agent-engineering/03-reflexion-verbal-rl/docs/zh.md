## 问题 问题引入

经纪人失败任务. 在标准RL中,你会运行数千个更多的试验,计算梯度,更新权重.昂贵,缓慢,大多数生产经纪人没有每次失败的训练预算.

> 代理人失败了某项任务. 在标准RL中,你需要运行数千次更多的试验,计算梯度,更新权重,昂贵,缓慢,而且大多数生产代理人没有针对每次失败的训练预算.

思考 (Shinn et al., arXiv:2303.11366) 提出了一个不同的问题:如果代理人只是想知道为什么它失败了,然后再试试一次?没有重量更新.没有梯度.

> 思考:如果代理人只是想想失败的原因,然后在下一次尝试的提示中加入这个想法吗?没有权重更新,没有梯度,只有试验间存储的自然语言.

结果:在ALFWorld上,它超过了ReAct和其他非精细调节的基线.在HotpotQA上,它在ReAct上改进.在代码生成 (HumanEval/MBPP) 上,它设置了当时的最先进状态.所有这些都没有单个梯度步骤.

> 结果:在ALFWorld上它击败了ReAct 和其他非微调基线.在HotpotQA上它超越了ReAct.在代码生成 (HumanEval/MBPP) 上它达到当时的最佳水平.

## 概念的核心概念

### 三个组成部分

```
Actor         : generates a trajectory (ReAct-style loop)     # 执行器：生成行动轨迹
Evaluator     : scores the trajectory — binary, heuristic, or self-eval  # 评估器：评分
Self-Reflector: writes a natural-language reflection on the failure      # 自我反思器：写反思
```

另外一个数据结构:

```
Episodic memory: list of prior reflections, prepended to the next trial's prompt  # 情景记忆
```

一次试验是演员.评价者评分.如果得分低,自反射器产生反射 ("我选择错误的工具,因为我读错了问题,因为问X,问Y").反射进入剧情记忆.下一次试验开始新鲜,但看到反射.

>  **【类比】**思考 像考试做错题后的"错题本"机制:你做错一道题 ((演员 失败)→ 得到对错信号 ((评价者 评分)→ 写下"我为什么错了" ((自反思写写反思)→ 下次考前翻错题本 ((情景记忆前置到提示) ⋅ 下次重复同类题,错误的概率就低了――关键是错题本 ((反思) 用自然语言写,不需要重新训练模型权重――

> 一次试运行 演员――评价者对其评分――如果分数低,自我反思者 生成一段反思――"我选错了工具,因为我把问题误解为问X,实际上问是Y")――反思存入情景记忆――下一次试验重新开始,但能看到反思――

### 三种评估者类型

1. **Scalar**外部二进制信号.ALFWorld成功或失败.HumanEval测试通过或失败.最简单,最高信号.
   翻译: 中文**标量**外部二元信号――ALF世界成功或失败――HumanEval 测试通过或不通过――最简单,信号最强――
2. **Heuristic**预定义失败签名. "如果代理在连续两次执行相同的操作,标记为被困. " "如果轨迹超过50步,标记为不有效. "
   翻译: 中文**启发式**预定义的失败签名:如果代理连续两次产生相同行动,标记为卡住.
3. **Self-evaluated**法学士的轨迹是自有的. 需要在没有基础真理时. 信号较弱;与工具基础验证 (课05  关键) 很好.
   翻译: 中文**自评估**LLM对自己的轨迹评分──在没有真价值时需要──信号较弱;与工具定验证 (第五课) 配合使用──

默认的2026是混合的:可用时的尺度,不用时的自行,

> ️ **【易错点】**三种评估器选错会出现大问题:在创意写作中,这种"无标准答案"的任务上硬上规模评估员 (如关键词匹配),将持续产生"失败信号"→代理 拼命反思 → 但反思本身没有意义 → 浪费代币直到耗尽预算──**后果**们都在着.**一行修复**首先使用5条样本手工验证"失败信号是否能区分好坏",区分不开就降级为自主评估+代上限――
