### 工具方案

每个提供商都有一个方案.

> 每个提供商都有自己的模式.

```
name: string
description: string (what it does, when to use it)
input_schema: JSON Schema (properties, required, types, enums)
```

人类用途 `input_schema`直接使用.`function.parameters`两个都接受JSON方案.描述承载量,模型阅读它们来选择正确的工具.不良的工具描述是错误的工具失败的第一根原因.

>  **【类比】**工具描述就像给实习生写的"使用说明书"――模型从来没有见过你的工具,它唯一可以依赖的就是描述――如果你写了`name: get_user, description: "gets user"`模型根本不知道是按身份证还是按邮箱查询,返回是完整的对象还是仅仅是姓名.**好描述包含三要素**做什么 + 何时用 + 输入输出语义。

> ️ **【易错点】**最常见的灾难:信任模型回归的参数类型――模型经常把`"5"`返回给期望`int`计划的.**后果**您的工具函数`TypeError`崩,整个代理循环中断.**一行修复**: 在工具执行入口统一做 `pydantic.BaseModel.parse_obj`或类似的校验,验证失败时返回结构性错误`{"error": "expected int, got str"}`让模型再试一次.

> 直接使用`input_schema`◎ 开放AI 使用`function.parameters`△两者都接受JSON方案. 描述是核心承载模型通过阅读描述来选择正确的工具.
