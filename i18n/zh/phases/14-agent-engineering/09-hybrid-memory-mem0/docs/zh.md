### 聚合分数

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **Relevance**向量共数,KV的确切匹配,图路径重量.
  翻译: 中文**相关性**向量余弦、KV 精确匹配、图路径权重──
- **Importance**标记在写作时间或学习 (一些事实更重要:名称,身份证,政策).
  翻译: 中文**重要性**写入时标记或学习得到 ((某些事实更重要:姓名、ID、策略) 👇
- **Recency**自上一次写或阅读以来,随时间的推移而呈指数级衰退.
  翻译: 中文**时效性**自上次写入或读取以来的时间指数下降.

按产品调整的重量.`w_recency`对于聊天代理人;更高`w_importance`对于合规代理人;`w_relevance`为了检索人员.

> ️ **【易错点】**三种权重照搬 Mem0 论文默认值(如 0.4/0.4/0.2) 直线**后果**根据"中国"的法律规定, 由于"中国"的新"昨天聊天气"被压下, 检索不到因为`w_recency`太高,老的高重要性事实被时间衰退淹没了.**一行修复**根据最新的情况, 根据重要性进行了测试调权重,不同产品方向完全不同.

> 权重按产品调优──聊天代理 使用更高的 `w_recency`合规代理 使用更高的 `w_importance`;检索代理 使用更高的 `w_relevance`,我知道.

### 范围分类

Mem0 分开记忆范围:

> 根据范围拆分记忆:

- **User memory**持续在整个会议中,按键开.`user_id`现在,我们要去.
  翻译: 中文**用户记忆**跨会话持久化,以`user_id`为了关键.
- **Session memory**在一个线程内持续.
  翻译: 中文**会话记忆**在一个线程内持久化.
- **Agent memory**每代理实例状态.
  翻译: 中文**Agent 记忆**每个代理 实例状态

每个写作都会选择一个范围. 检索可以通过每个范围的权重进行查询. 混合范围是如何得到"助理告诉爱丽丝关于勃的项目"事件.

>  **【困惑】**问:MEM0 三种储备必须部署运维,对于小团队来说成本太高,能不能只使用向量库吗?**纯聊天机器人**用量库 + KV就够了 ((少于90% 复杂度);**多用户企业 Agent**对于"Alice 见 Bob 的数据"的事件,Mem0 的三存储库是"为合规而生"的设计,不是所有场景都需要的.

> 每次写入选择一个范围.检查可以跨范围查询,带每个范围权重.不经过思考地混合范围会导致"助手告诉爱丽丝关于Bob项目"事件.

### 在这个模式出现错误的地方

- **Embedding drift.**随着体积的增长,向量结果在第一百个查询中会降低.
  翻译: 中文**嵌入漂移。**随着语料的增长和退化而出现正确的向量结果.
- **KV schema creep.** `(user_id, type, entity)`看起来很简单,直到每个团队都加入了自己的团队.`type`季度检查类型.
  翻译: 中文**KV 模式蔓延。** `(user_id, type, entity)`看起来很简单,直到每个团队增加自己的.`type`△每季度审计类型集
- **Graph explosion.**一个噪音的提取器每条消息增加了50个边缘.`add`让人们放弃低信心的边缘.
  翻译: 中文**图爆炸。**一个杂的提取器每条消息加50条边缘.`add`调用图写入数;丢弃低置信度边缘.

## 关键词 快速查找表

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| 术语 | 通俗说法 | 实际含义 |
| Hybrid memory | "Vector plus graph plus KV" / "向量加图加 KV" | Three stores written in parallel, fused on retrieval / 三个存储并行写入，检索时融合 |
| Fact extraction | "Memory ingestion" / "记忆摄取" | LLM step that breaks text into (entity, relation, fact) tuples / 将文本拆分为（实体、关系、事实）元组的 LLM 步骤 |
| Fusion scoring | "Relevance ranking" / "相关性排序" | Weighted sum of relevance, importance, recency / 相关性、重要性、时效性的加权和 |
| Scope | "Memory namespace" / "记忆命名空间" | user / session / agent — determines who sees what / 用户/会话/Agent——决定谁看到什么 |
| Mem0g | "Memory graph" / "记忆图" | Typed edges with temporal validity for relationship queries / 带时序有效性的类型化边，用于关系查询 |
| Temporal invalidation | "Soft delete" / "软删除" | Mark contradicted edges invalid; never delete / 标记矛盾边为无效；永不删除 |
| Embedding drift | "Retrieval rot" / "检索腐化" | Vector quality degrades as corpus grows; re-embed periodically / 向量质量随语料增长退化；定期重新嵌入 |
