## 问题 问题引入

团队有子团队,公司有部门.等级结构反映了这一点.

> 一旦监督者模式被理解,自然下一步是"如果工作器本身也是监督者?"团队有子团队;公司有部门.

由于人类组织以这种方式工作,诱惑是强大的. 但LLM等级继承了人类等级的所有病理 (信息丢失,沟通错误,缓慢的代)

> 诱惑很强,因为人类组织这样工作. 但LLM层次继承了人类层次的所有病态,但没有人类关系和共享文化的稳定效果.

问题:LLM经理与人经理不同.一个人经理对他们的报告有稳定的前.一个LLM经理从任何情况下都重新考虑组织.

> 问题在于:LLM管理员与人类管理员不同.人类管理员对其下属知道有什么稳定的先验.LLM管理员每轮从上下文中重新推论组织.

管理层级的错误是每一个管理层级的错误. 上层的5%的错误分配将在3级的25%,因为每个级别重新解释了 (已经错误的) 委托.

> 这是分层LLM系统的核心失败模式:每个管理层层次的错误增加了上层次的错误.

## 概念的核心概念

### 形状

```
                 Manager
                 ┌─────┐
                 └──┬──┘
           ┌────────┴────────┐
           ▼                 ▼
       Sub-Mgr A         Sub-Mgr B
       ┌─────┐           ┌─────┐
       └──┬──┘           └──┬──┘
         ┌┴──┬──┐          ┌┴──┐
         ▼   ▼  ▼          ▼   ▼
       W1  W2  W3         W4  W5
```

每个内部节点都会进行计划,委托和合成.

> 每个内部节点规划,委派和综合――只有叶子节点做实际工作――

这反映了人类器官图表,它既是强度 (熟悉的心理模型) 和弱点 (人类器官具有 LLM 缺乏的稳定前).每个 LLM 级别都从零开始重新推理了器官.

> 这反映了人类组织结构,这既是其优势 (熟悉的心智模型) 也是其弱点 (人类组织有LLM缺乏稳定的先验).

### 在它破裂的地方

两次失败模式,2026年后的测试继续发现:

> 2026年后分析不断发现三种失败模式:

杰姆里等人 (MAST, arXiv:2503.13657) 记录了这些作为"规范失败"和"人际间错误排列"子组.等级系统显示它们比平坦的更为重要,因为每个级别都增加了重新解释步骤.

> 杰姆里等) 将这些记录为"规范失败"和"人际不对齐"子家族.

1. **Task assignment error.**由于副经理顺服地工作于它所给出的,错误只会在顶部合成一个层次从一个人可能抓住它.
   翻译: 中文**任务分配错误。**管理者读取目标,幻觉出解,并委托给错误的子管理者──因为子管理者服从处理给定的任务,错误只在顶层综合时浮现比人类本可以捕获的位置高一层──
2. **Output misinterpretation.**副管理员返回"无法验证X索赔".顶级管理员总结为"X索赔未确认".意思在每个级别上波动.
   翻译: 中文**输出误解。**管理者返回"无法验证声明 X──"顶层管理者总结为"声明 X未确认──"含义在每个层都漂移──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
3. **Consensus loops.**两位副经理不同意;最高经理要求他们和解;他们重新委托下;工人重新运行;副经理回应稍微不同的答案;循环.`Process.hierarchical`现在这个限制本身就是一个超参数.
   翻译: 中文**共识循环。**两个子管理员不一致;上层管理员要求他们协调;他们向下重新委托;工作器重新运行;子管理员回归有略有不同的答案;循环――工作人员的`Process.hierarchical`通过步骤限制来保护,但限制本身现在是一个超参数.

## 关键词 快速查找表

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Hierarchical / 分层 | "Org chart pattern" / "组织架构模式" | Supervisors over supervisors; only leaves do work. / 监督者之上还有监督者；只有叶子节点做实际工作。 |
| Manager LLM / 管理者 LLM | "The boss" / "老板" | The LLM that decomposes, assigns, and validates at an internal node. / 在内部节点进行分解、分配和验证的 LLM。 |
| Decomposition drift / 分解漂移 | "The boss lost the plot" / "老板偏离了主题" | Top manager's split no longer covers the original question. / 顶层管理者的拆分不再覆盖原始问题。 |
| Reconciliation loop / 协调循环 | "Endless meetings" / "无尽会议" | Sub-managers disagree; top re-delegates; workers re-run; loop until budget exhausted. / 子管理者不一致；顶层重新委派；工作器重新运行；循环直到预算耗尽。 |
| Depth-2 ceiling / 深度-2 上限 | "Don't go deeper than 2 levels" / "不要超过 2 层" | Empirical guardrail: 3+ levels collapses observability. / 经验防护：3+ 层使可观测性崩溃。 |
| Canary question / 金丝雀问题 | "Ground truth at every level" / "每层的基准真相" | A worker that is always asked the original query unchanged, to detect drift. / 一个总是被问及原始查询不变的工作器，用于检测漂移。 |
| Provenance chain / 来源链 | "Who said what" / "谁说了什么" | Trace from each synthesis back to the leaf outputs that produced it. / 从每个综合追溯到产生它的叶子输出。 |
