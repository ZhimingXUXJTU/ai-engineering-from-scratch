## 概念的核心概念

### 两个原始人

**Routine.**系统提示,定义代理人的角色和可用的工具. 想象它像一个有范围的指令集:"你是一个分类代理;如果用户询问退款,请交给退款代理.

> **例程。**定义代理角色和可用工具的系统提示.把它想象成一个范围范围的指令:"你是一个分诊代理;如果用户询问退款,交给退款代理.

**Handoff.**群运行时间检测到代理返回值,并将活跃代理转换为下一个轮.

> **交接。**代理可调用工具,返回一个新的代理对象.

这就是整个抽象.

> 这就是整个抽象.

```
def transfer_to_refunds():
    return refund_agent  # Swarm sees Agent return → switch active agent

triage_agent = Agent(
    name="triage",
    instructions="Route the user to the right specialist.",
    functions=[transfer_to_refunds, transfer_to_sales, transfer_to_support],
)
```

根据用户的信息,分类代理的系统提示使其选择正确的交付.

> 分诊 代理的系统提示使其根据用户消息选择正确的交接.

现在,我们需要一个新的工具,一个新的数据集,一个新的图表编辑器,一个新的状态机器.

> 这是一个优雅的举措:复用模型现有的工具调用基础设施进行编排.没有新的DSL,没有图片编辑器,没有状态机.模型已经知道如何选择正确的工具;交接只是返回代理的工具.

- **Small API.**需要学习的两个概念.
  翻译: 中文**小型 API。**只有学习两个概念.

  翻译: 中文**使用模型已有的能力。**工具调用已在各供应商中是生产阶段.

  翻译: 中文**无状态机负担。**你不描述图; 代理的提示描述它们交给谁.

### 无国籍贸易

运行期间,该框架保留了消息历史,但它没有保留任何东西.内存,连续性,长时间运行任务所有电话调用者的问题.

> 运行间的群确实是无状态的. 框架在运行期间保持消息历史,但没有持久任何东西.

无状态设计是有意的:它使框架轻微重启,水平可扩展和可调试 (每个运行都是独立的).成本是长期运行的工作流需要外部状态管理 (数据库,排队,检查站).

> 无状态设计是有意义的:它使框架可以轻松重启,水平扩展和调试,每次运行独立.

在生产中 (OpenAI Agents SDK,2025年3月) 这是一个主要的变化:SDK添加了内置的会议管理,防护窗和追踪,同时保持了原始的交付.

> 在生产环境中,OpenAI Agents SDK,2025年3月),这是一个主要的变化:SDK 增加了内置会话管理,防护和追踪,同时保留了交接原语──
