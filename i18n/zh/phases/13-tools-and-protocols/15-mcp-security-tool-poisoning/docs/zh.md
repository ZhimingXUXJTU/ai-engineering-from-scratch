### 值得检查的7个攻击面

为了保持谨慎,不要使用模糊的指令,而是用具体的列表.

> 为了让我们可以理解,

> **【中文解读】**七个攻击面:元数据投毒、描述符地毯拉、跨服务器影射、头/正文混、能力冒起升级、MRTR 状态改、供应链身份混──注意它们相互重叠哈希锁定只防"变化"防不了"初版即毒",静态扫描只抓住明显短语,命名空间只消一类冲突──必须叠加控制──

1. **Metadata poisoning.**描述包含与声明的工具行为无关的指令.
  翻译: 中文**元数据投毒。**描述中包含与声明的工具行为无关的指令.
2. **Descriptor rug pull.**已批准的名称,描述,方案或注释变化.
  翻译: 中文**描述符地毯拉扯。**已批准的名称,描述,方案或注解发生变化.
3. **Cross-server shadowing.**两个后端都显示出相同的无条件工具名称,路由则默默地选择一个.
  翻译: 中文**跨服务器影射。**两次后端曝光同名未限工具名,路由静默选择其一.
4. **Header and body confusion.** `Mcp-Method`或`Mcp-Name`不同意JSON-RPC请求.
  翻译: 中文**头/正文混淆。** `Mcp-Method`或`Mcp-Name`与JSON-RPC 请求不一致.
5. **Capability escalation.**一个同行声称一个扩展或客户端功能,服务器误会该声明授权.
  翻译: 中文**能力冒用升级。**服务器误认为声明是授权的.
6. **MRTR state tampering.**客户改变`requestState`答案不同问题,或用不同的论点重新确认.
  翻译: 中文**MRTR 状态篡改。**客户端改 `requestState`、回答另一个问题,或把确认换参数重复使用.
7. **Supply-chain identity confusion.**已知显示名称被视为出版商或服务器身份证明.
  翻译: 中文**供应链身份混淆。**熟悉的展示名字被当作发行者或服务器身份证明.

这些表面重叠.哈希粘贴有助于描述符的更改,但并不能证明第一个描述符是安全的.静态扫描捕获明显的短语,但不是微妙的指示.命名空间防止一个碰撞类,但不是恶意的名称空间服务器.堆控制.

> 这些攻击面相互重叠. 哈希锁定有助于发现描述符变化,但证明没有第一个描述符是安全的.静态扫描能抓住明显短语,抓不到隐命令;命名空间能防一类冲突,防不了恶意带命名空间服务器――所以需要叠加控制.

### 在政策之前验证路由

> **【中文解读】**路由校验必须先于策略:`Mcp-Method`必须等于正文方法,`Mcp-Name`必须等于`params.name`没有任何不同意的`-32020`拒绝并且应发生在选择后端,应用RBAC,扣限制流令牌之前.`-32020`头文一致但版本不支持 → HTTP 400 `-32022`且`data`精确为`{"supported":["2026-07-28"],"requested":"<actual>"}`没有任何信息`-32601`没有通知`id`永远不收到JSON-RPC成功/错误响应,HTTP 层接受后返回 202 空体──

为了`tools/call`流式HTTP包括:

```text
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: notes.export
```

标题方法必须等于体型方法.标题名称必须等于`params.name`拒绝与`-32020`在选择后端,应用RBAC或消耗利率限制令牌之前.

> 头条的方法必须等于正文方法,头条的名称必须等于`params.name`△不一致时用`-32020`拒绝要在选择后端,应用RBAC,消耗限制流令牌之前完成.

这种排序消除了一个常见的模糊性:一个组件授权了机器,而另一个由头条路径.

> 这个顺序堵住一个常见差异:一个组件按正文做授权,另一个组件按路由头做转发.

> ️ **【易错点】**场景:组件A按JSON-RPC 正文做授权,组件B按 `Mcp-Name`头做路由,头与正文不一致时没人拦截 / 后果:攻击者构建"正文说注释.搜索、头说注释.出口"的请求绕过授权直达高危工具 / 修复:(1) 固定校验顺序先校验 JSON-RPC 与元数据类型,再对对对对头与正文相等,最后检查版本支持;(2) 头文不一致一律 HTTP 400`-32020`限流令牌在全部校验中通过后才减免,防止垃圾请求燃烧光配额.

电线验证遵循一个确切的序列.验证JSON-RPC和元数据类型,与体格比较标题值,然后检查是否支持匹配的版本.一个不匹配的标题返回HTTP 400`-32020`如果标题和体格同意不支持的版本,请返回HTTP 400`-32022`其他`data`完全是`{"supported":["2026-07-28"],"requested":"<actual>"}`未知方法返回了HTTP 404`-32601`现在,我们要去.

> 线格式校验遵循唯一精确的顺序:先校验JSON-RPC与元数据类型,再比对头值与正文,最后检查是否支持匹配到的版本.头不匹配返回HTTP 400.`-32020`标题一致但版本不支持,返回HTTP 400 `-32022`且`data`精确为`{"supported":["2026-07-28"],"requested":"<actual>"}`无法返回HTTP 404`-32601`,我知道.

每个错误对象都包含了可选的`data`合同需要结构化回收信息.`id`通过 HTTP 通知,它将返回 202 个空体.

> 当协议需要结构化恢复信息时,每个错误对象都带有可选的选择.`data`没有通知`id`由于此,永远不接受JSON-RPC成功或错误响应.

### 执行前的权力减少

无国籍本身并不是安全性.它删除了隐藏的协议历史,但一个自主请求仍然可以要求一个超级权力处理器泄露数据或进行不可逆转的变化.安全性来自于减少每个边界的权威:

> 仅靠无状态不安全. 它移除了隐藏的协议历史,但一个自含的请求仍然可能让权限过大处理器泄露数据或做不可逆变.

1. **Typed verb.**设置一个有限的操作,例如`archive_note`没有一般药物`run`或`request`工具可以表达无关权力.
  翻译: 中文**类型化动词。**暴露一个有界限操作如`archive_note`没有任何关键权力.`run`或`request`工具.
2. **Validated arguments.**使用一个关闭的方案,在政策评估之前,将未知的字段拒绝,一次正常化识别符,限制大小,并验证目的地,租户和资源所有权.
  翻译: 中文**校验过的参数。**尽可能使用封闭方案,拒绝未知字段,标识符只规范化一次,限制大小,并评估前校目的地,租户和资源归属的策略.
3. **Current authorization.**绑定验证的主题与精确的动词,资源,环境和正常化参数.工具注释和客户端功能不赋予此权限.
  翻译: 中文**现行授权。**通过将已认证的主体绑定到精确的动词,资源,环境和规范化参数.
4. **Action-bound approval.**为了获得后果调用,将批准绑定到输入的动词和正常化参数的摘录,加上主题,过期和一次性政策.任何改变的字段都需要新的决定.
  翻译: 中文**绑定动作的批准。**对于后果调整,把批准绑定到"类型化动词 + 规范化参数"的摘要,外加主体,过期时间和一次性策略.
5. **First-class refusal.**拒绝模型,过期批准,用户拒绝,不安全的目的地作为普通结果,不会产生任何副作用.不要把拒绝转化为更弱的反弹工具.
  翻译: 中文**一等公民式的拒绝。**拒绝,过期批准,用户拒绝和不安全的目的,作为不执行副作用的普通结果建模,不要把拒绝转化为更弱的底工具.
6. **Redacted audit evidence.**记录谁问,哪个承认描述符和政策版本使用,什么正常目标被授权,为什么决定允许或拒绝,以及是否开始执行.
  翻译: 中文**脱敏的审计证据。**记录谁发起了,使用了哪个准入描述符和策略版本,授权了什么规范目标,决定为什么允许或拒绝,是否开始执行.

每一步都缩小了下一个组件可能做的事情.最终处理器应该收到已经验证的域命令,而不是原始模型文本加上广泛的凭证.在MRTR重试,任务更新或网关转发呼叫时重复整个链接.早期的批准不会将后来的请求转化为可信的会话流量.

> 每一步都缩小下一组件能做的事――最终处理器应收到已经验的领域命令,而不是原始模型文本加宽凭证――MRTR 重试、任务更新或网关转发时必须重跑整条链――早先的批准不会使后续请求成为可信的会话流量――
