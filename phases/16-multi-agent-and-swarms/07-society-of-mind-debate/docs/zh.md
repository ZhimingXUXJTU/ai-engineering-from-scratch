# 心智社会与多 Agent 辩论 | 心智社会 多 Agent 辩论

> Minsky 1986 年的前提——智能是专家的社会——每隔十年被重新发现。2023 年 Du 等人将其转化为具体算法：多个 LLM 实例提出答案，阅读彼此的答案，批评并更新。经过 N 轮，它们收敛于一个共识，在六个推理和事实性任务上击败了零样本 CoT 和反思。两个发现很重要：**多个 Agent**和**多轮**都独立贡献。社会击败单 Agent 独白；多轮交换击败单次投票。

> **【拓展：society of mind debate→具体应用】** Marvin Minsky 的《心智社会》（1986）提出智能是许多简单心智的协作产物。这一思想在 2026 年的多 Agent 辩论系统中实现——多个 Agent 从不同角度讨论问题，通过辩论达成更好的结论。研究表明，3-5 个 Agent 的辩论效果最佳。

## 问题引入

自一致性——对一个模型采样多次并取多数答案——是你可以附加的最便宜的推理改进。它有效，但很快就饱和了。你可以加倍采样数量而看不到有意义的跳跃。

辩论打破了饱和。不是从一个模型中采样 N 个独立样本，而是 N 个 Agent 阅读彼此的推理并修订。样本之间的相关性下降（它们不再是独立同分布的），收敛点通常是正确的，而独立同分布投票则是自信地错误的。

## 核心概念

### Du 等人 2023 算法

来自 arXiv:2305.14325（ICML 2024）：

1. N 个 Agent 中的每个都对问题产生初始答案。
2. 对于轮次 r = 2..R：每个 Agent 看到其他 Agent 的第 r-1 轮答案，并被要求"考虑到这些，给出你更新的答案。"
3. 经过 R 轮后，对最终答案进行多数投票。

论文在 MMLU、GSM8K、传记、MATH 和事实性基准上进行了测试。辩论持续击败 CoT 和自我反思。

### 两个独立的旋钮

来自同一论文的消融：

- **仅增加 Agent 数量**（1 轮，N 的多数投票）在大多数任务上击败单 Agent，但会饱和。
- **仅增加轮次**（1 个 Agent 看到自己先前的推理）几乎没有帮助——反思的已知弱点。
- **两者结合**产生大跳跃。多个 Agent 之间的多轮交换驱动了收益。

### 为什么它有效

两个机制：

1. **接触分歧。** 当 Agent 看到另一个 Agent 带有不同结论的推理链时，它必须要么论证要么更新。无论哪种方式，第 r+1 轮的上下文都比第 r 轮更丰富。
2. **相关错误减少。** 在自一致性中，所有样本来自同一模型，所以错误是相关的——你平均到一个自信地错误的答案。不同的模型或不同的种子去相关。不同的*辩论观点*进一步去相关。

### 异构辩论

A-HMAD 和相关后续工作为不同的 Agent 使用*不同的基础模型*。Llama + Claude + GPT 辩论减少了单一文化崩溃（第 26 课），因为一个模型族的相关错误不被其他族共享。

缺点：弱模型参与辩论可以将共识拖向其错误答案（参见"我们应该进行 MAD 吗？"，arXiv:2311.17371）。

### NLSOM — 129 个 Agent 的扩展

Zhuge 等人（"自然语言心智社会中的心智风暴"，arXiv:2305.17066）将此想法扩展到 129 成员社会。结果：专业化和自组织随规模涌现，系统在视觉问答等任务上超越单 Agent。

### 失败模式

- **谄媚级联。** 所有 Agent 顺从听起来最自信的 Agent。辩论崩溃为最大声的声音。提示对抗性角色（"一个 Agent 必须论证反方立场"）有帮助。
- **主题漂移。** 多轮辩论从原始问题漂移。缓解：每轮重新注入问题。
- **计算爆炸。** N 个 Agent × R 轮 = N·R 次 LLM 调用，每次都有增长的上下文。5 Agent、5 轮的辩论是 25 次调用，上下文不断增长。每个问题的成本可能超过单次 CoT 调用的 10 倍。

## 动手构建

`code/main.py` 在一个数学问题上运行 3 Agent × 3 轮辩论，每个 Agent 从不同的（可能是错误的）答案开始。Agent 是脚本化的——每个"更新"通过加权邻居答案的加权平均。收敛在逐轮日志中可见。

演示显示两个关键效果：

- 单轮交换将 Agent 移向更接近正确答案。
- 第 2 轮之后的额外轮次显示收益递减（匹配 Du 等人的平台）。

运行：

```
python3 code/main.py
```

## 用框架实现

`outputs/skill-debate-configurator.md` 为新任务配置辩论：Agent 数量、轮次数、异构性（相同模型 vs 混合）、角色分配（对称 vs 一个对抗）。它还在你运行之前估算 token 成本。

## 产出物

如果你发布辩论：

- **将轮次限制在 3。** Du 等人显示 3 轮捕获了大部分收益。更多是成本，不是质量。
- **将 Agent 限制在 5。** 超过 5 个，上下文膨胀和成本占主导。
- **默认异构。** 池中至少有两个不同的基础模型。
- **对抗性席位。** 一个 Agent 被提示为无论如何都不同意。打破谄媚。
- **记录每一轮。** 隐藏中间轮的辩论系统无法被调试或审计。

## 练习题

1. 运行 `code/main.py`，然后将轮次数设置为 5，观察收益递减。在哪个轮次额外收敛停止？
2. 添加第四个具有对抗角色的 Agent：始终不同意当前多数。这是打破还是改善收敛？
3. 绘制（打印）每轮的一致性分数（多数答案上的 Agent 比例）。它何时达到 1.0，这是否等同于"正确"？
4. 阅读 Du 等人第 4 节消融。使用此代码复现"仅 Agent"与"仅轮次"与"两者"的结果。
5. 阅读"我们应该进行 MAD 吗？"（arXiv:2311.17371）并列出轮询之外的两种辩论变体——例如，法官主导、辩论链、对抗式。
