# 指令遵循作为对齐信号

> 后续每一课对 RLHF 的批评都是针对这条管线的。在你研究优化压力如何扭曲代理指标之前，你必须先看到这个代理指标。InstructGPT（Ouyang 等人, 2022）定义了参考架构：在指令-响应对上进行监督微调，在成对偏好排序上训练奖励模型，以及带 KL 惩罚的 PPO。1.3B 的 InstructGPT 优于 175B 的 GPT-3。正是这一结果，使得 2026 年每个前沿实验室仍然部署 RLHF 形式的后训练管线。

> **【中文解读】** InstructGPT（Ouyang 等人, 2022）定义了对齐的参考架构：1) 监督微调（SFT）在指令-响应对上训练；2) 奖励模型在成对偏好排序上训练；3) PPO 对抗奖励模型，带 KL 惩罚保护。1.3B 的 InstructGPT 在人类偏好评估上超越了 175B 的 GPT-3。这就是为什么 2026 年每个前沿实验室仍在使用 RLHF 形式的后训练管线。

> **【拓展：RLHF → 现代 AI 对齐】** RLHF（基于人类反馈的强化学习）是 ChatGPT 成功的关键技术。InstructGPT 的三阶段管线——SFT→RM→PPO——已成为行业标准。2026 年的变体包括 DPO（直接偏好优化）、Constitutional AI（宪法 AI）等，但核心思路相同：用人类偏好信号引导模型行为。

## 学习目标

- 说出 InstructGPT 管线的三个阶段及每个阶段使用的损失函数。
- 解释为什么 1.3B 的指令微调模型在人类偏好评估上超越了原始 175B GPT-3。
- 说明第 3 阶段的 KL 惩罚在防止什么问题，以及移除它为什么会退化为模式搜索行为。
- 描述对齐税以及 Ouyang 等人使用的 PPO-ptx 缓解措施。

## 问题引入

预训练语言模型完成文本。它们不回答问题。问 GPT-3 "写一个反转列表的 Python 函数"，你经常会得到另一个提示，因为大部分训练分布是继续更多网络文本的网页文本。模型在完成它的任务——只是任务本身是错的。

每个严肃实验室用来修复这个问题的代理指标是人类偏好。两个补全发给标注者；标注者选择更好的一个；奖励模型学习标注者的偏好。然后 RL 循环将策略转向奖励模型打分高的输出。这就是 InstructGPT 的完整论点，三句话说完。论文的其余部分是工程细节。

## 核心概念

### 阶段 1：监督微调（SFT）

收集提示-响应对，其中响应是一个善意人类会写的内容。Ouyang 等人使用了标注者和 OpenAI API 的 13k 提示。用标准交叉熵损失在这个数据上微调基础模型。

SFT 给你的东西：模型现在回答问题而不是继续问题。它不给你的东西：关于多个合理答案中标注者偏好哪个的任何信号。

> **【中文解读】** SFT 阶段使模型从"补全文本"转向"回答问题"，但无法提供关于多个合理答案中哪个更好的信号。RM 阶段使用 Bradley-Terry 成对偏好损失 L_RM = -log sigmoid(r(x,y_w) - r(x,y_l)) 在标注者排序的补全对上训练奖励模型。RM 通常从 SFT 模型初始化并替换 LM 头为标量头，6B 就足以指导 175B 模型。

### 阶段 2：奖励模型（RM）

对于每个提示，从 SFT 模型采样 K 个补全。标注者对它们排序。训练一个奖励模型，对任何提示-响应对打分，使得对于 `y_w` 被偏好于 `y_l` 的对：

```
L_RM = -log sigmoid(r(x, y_w) - r(x, y_l))
```

这是 Bradley-Terry 成对偏好损失。RM 通常从 SFT 模型初始化，将 LM 头替换为标量头。

奖励模型很小：6B 就足以指导 175B 的 InstructGPT。它们也很脆弱——论文第 5 节主要是关于小规模出现的奖励黑客行为。

> **【拓展：PPO 阶段 → RLHF 的核心工程】** PPO 阶段的目标函数 J(pi) = E[r(x,y)] - beta * KL(pi || pi_SFT) 最大化奖励同时保持策略接近 SFT。KL 系数 beta 是最重要的 RLHF 超参数——太低导致奖励黑客，太高则 SFT 上无改进。没有 KL 项，优化器找到的是 RM 从未见过的对抗样本——分数高不是因为人类真正偏好，而是因为 RM 从未评估过这些输入。

### 阶段 3：带 KL 惩罚的 PPO

定义目标：

```
J(pi) = E_{x~D, y~pi(.|x)} [ r(x, y) ] - beta * KL(pi(.|x) || pi_SFT(.|x))
```

用 PPO 最大化。KL 项使 `pi` 不会偏离 SFT 策略太远。没有它，优化器找到的是对抗样本——在 RM 下得分高的字符串，因为 RM 从未见过它们，而不是因为人类真正偏好它们。

KL 系数 `beta` 是最重要的 RLHF 超参数。太低：奖励黑客。太高：相比 SFT 没有改进。

> **【中文解读】** 对齐税：RLHF 后模型在人类偏好上更好但在标准基准（SQuAD, HellaSwag, DROP）上退步。Ouyang 等人称之为"对齐税"并用 PPO-ptx 修复——将预训练梯度混入 RL 目标，使模型不忘记从未被奖励过的下游任务。PPO-ptx 成为标准——Anthropic、DeepMind 和 Meta 都使用某种变体。

### 对齐税

RLHF 后，模型更受人类偏好但在标准基准（SQuAD、HellaSwag、DROP）上退步。Ouyang 等人将此称为对齐税，并用 PPO-ptx 修复：将预训练梯度混入 RL 目标，使模型不会忘记从未被奖励过的下游任务。

```
J_ptx(pi) = J(pi) + gamma * E_{x~D_pretrain} [ log pi(x) ]
```

PPO-ptx 成为标准。Anthropic、DeepMind 和 Meta 都使用某种变体。

> **【拓展：1.3B vs 175B → 对齐独立于能力】** 1.3B InstructGPT 在标注者偏好上约 70% 的时间胜过 175B GPT-3。差距在生产流量隐藏测试提示上更大。两个要点：（1）对齐是与能力不同的轴——175B 有更多能力，1.3B 有更多对齐，标注者偏好对齐的；（2）能力下限由基础模型设定——你不能 RLHF 一个基础模型使其知道它从未见过的事实。

### 结果

1.3B 的 InstructGPT（SFT + RM + PPO-ptx）在标注者偏好上约 70% 的时间优于 175B 的基础 GPT-3。在生产流量的隐藏测试提示上差距更大。从这组数据可以读出两点：

1. 对齐是与能力不同的轴。175B 模型有更多能力；1.3B 模型有更多对齐；标注者偏好对齐的模型。
2. 能力下限由基础模型设定。你不能通过 RLHF 让基础模型知道它从未见过的事实。

## 用框架实现

`code/main.py` 在玩具偏好数据上模拟三个阶段。基础"策略"是动作 {A, B, C} 上的有偏硬币。阶段 1 SFT 模拟 200 个提示上的标注者动作。阶段 2 从 500 个成对排序中拟合 Bradley-Terry 奖励模型。阶段 3 运行带 KL 惩罚的简化 PPO 更新。你可以观察奖励攀升、KL 散度增长和策略漂移——也可以关闭 KL 项，在 50 个更新步骤内看到奖励黑客出现。

关注点：

- `beta = 0.1` vs `beta = 0.0` 的奖励轨迹。
- 训练步骤中的 KL(pi || pi_SFT)。
- 最终动作分布与标注者偏好的比较。

## 术语速查表

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| SFT | "指令微调" | 阶段 1：在提示-响应对上用交叉熵微调 |
| 奖励模型 | "RM" | 在成对标签上用 Bradley-Terry 训练的 (提示, 响应) 标量回归器 |
| Bradley-Terry | "成对偏好损失" | -log sigmoid(r_w - r_l)；将成对排序归结为二分类 |
| KL 惩罚 | "正则化器" | `beta * KL(pi \|\| pi_SFT)`——保持 RL 策略接近 SFT 锚点 |
| PPO-ptx | "带预训练混合的 PPO" | 在 PPO 目标中加入部分预训练对数似然以抵消对齐税 |
| 对齐税 | "RLHF 回归" | RLHF 后 RLHF 未针对的标准基准上的下降 |
| 标注者偏好 | "地面真相" | 人类排序的样本；RM 是其统计代理，而非"人类价值观"的代理 |
