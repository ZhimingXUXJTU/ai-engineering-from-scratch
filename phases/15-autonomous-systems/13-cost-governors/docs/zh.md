# 操作预算、迭代上限和成本治理器

> 一个中型电商 Agent 的月度 LLM 成本从 1,200 美元跳到 4,800 美元，在其团队启用"订单追踪"技能之后。这不是定价错误。这是一个 Agent 找到了新循环并在其中持续消耗。Microsoft 的 Agent 治理工具包（2026 年 4 月 2 日）编纂了对这类失败的防御：每请求的 `max_tokens`、每任务的 Token 和金额预算、每日/每月上限、迭代上限、分层模型路由、提示缓存、上下文窗口化、昂贵操作的 HITL 检查点、预算违规时的终止开关。Anthropic 的 Claude Code Agent SDK 以不同名称发布相同的原语。金融速率限制——例如 10 分钟内超过 50 美元即切断访问——比月度上限更快捕获循环。

**类型：** 学习
**语言：** Python（标准库，分层成本治理器模拟器）
**前置条件：** Phase 15 · 10（权限模式），Phase 15 · 12（持久执行）
**时间：** ~60 分钟

## 问题引入

> **【中文解读】** 成本控制器（Cost Governors）监控和限制 Agent 的资源消耗——主要是 API 调用费用和 token 使用量。没有成本控制器的 Agent 可能在循环或低效执行中产生巨额账单。三种控制策略：(1) 预算上限——硬性 token/费用限制；(2) 速率限制——每分钟/每小时调用上限；(3) 效率门控——当成本/收益比恶化时暂停。

> **【拓展：cost governors】** 成本控制是 2025-2026 年 Agent 生产部署的关键挑战。公开案例：多个用户报告编码 Agent 在陷入修复循环后产生数千美元的 API 费用。解决方案包括：(1) OpenAI 的 max_output_tokens 限制；(2) Anthropic 的 usage tracking API；(3) 第三方工具如 Helicone 和 Braintrust 的成本监控。最佳实践是为每个任务设置明确的成本上限。

自主 Agent 在每轮上花费真金白银。聊天机器人的糟糕输出是一个糟糕的回复；Agent 的糟糕循环是一笔账单。业界记录的失败模式术语是"钱包拒绝服务 (Denial of Wallet)"——Agent 持续推理、持续工具调用、持续计费，没有什么能阻止它，因为没有设计任何东西来阻止它。

修复不是一个数字。它是在不同时间尺度和粒度上的限制堆栈：每请求、每任务、每小时、每天、每月。一个设计良好的堆栈在几分钟内捕获失控循环，在几小时内捕获缓慢泄漏，在一天内捕获糟糕的发布。同一个堆栈在 Agent 长程且自主时保持预算。

> **【中文解读】** 本节介绍了 AI Agent 的核心概念和实现方法。Agent 是 LLM 驱动的自主系统，能够观察环境、思考决策、执行行动并循环迭代直到完成目标。

这是一节工程课：数学是简单的，纪律是团队失败的地方。下面的限制列表全部在 Microsoft Agent 治理工具包或 Anthropic Claude Code Agent SDK 文档中命名。

## 核心概念

### 成本治理器堆栈

1. **每请求 `max_tokens`。** 简单。防止任何单次调用发出无限长的补全。
2. **每任务 Token 预算。** 在整个运行中，不超过 N 个 Token。在上限处硬停止。
3. **每任务金额预算。** 与 Token 相同但以货币计。Claude Code 中的 `max_budget_usd`。
4. **每工具调用上限。** 不超过 N 次 `WebFetch` 调用，N 次 `shell_exec` 调用等。
5. **迭代上限（`max_turns`）。** 总 Agent 循环迭代；防止无限推理循环。
6. **每分钟/每小时/每天/每月上限。** 滚动窗口。在不同时间尺度捕获泄漏。
7. **金融速率限制。** 例如，"如果 10 分钟内花费超过 50 美元，切断访问。"在月度上限触发前捕获基于循环的消耗。
8. **分层模型路由。** 默认使用较小的模型；仅当分类器判断任务需要时升级到较大的模型。
9. **提示缓存。** 系统提示和稳定上下文存储在提供商缓存中；重新发送的 Token 成本接近零。
10. **上下文窗口化。** 压缩/摘要以将活跃上下文保持在阈值以下；直接的 Token 成本降低。
11. **昂贵操作的 HITL 检查点。** 在已知昂贵的操作（长时间工具调用、大量下载、昂贵的模型升级）之前，要求人类点击。
12. **预算违规时的终止开关。** 任何上限触发时会话终止。上限被记录；需要单独的重新启用路径。

### 为什么是堆栈，而不是一个上限

单一的月度上限只在钱包空了之后捕获失控 Agent。单一的每请求上限在会话级别什么都捕获不到。不同的失败模式需要不同的时间尺度：

- **失控循环**（Agent 困在 5 秒重试中）：被速率限制捕获。
- **缓慢泄漏**（Agent 每任务做约 2 倍预期工作）：被每日上限捕获。
- **糟糕的发布**（新版本使用 5 倍 Token）：被每周/月度上限捕获。
- **合法激增**（真实需求，不是错误）：被小时/天上限配合清晰日志捕获。

### Claude Code 的预算面

Claude Code Agent SDK 暴露（公开文档）：

- `max_turns` — 迭代上限。
- `max_budget_usd` — 金额上限；违规时会话终止。
- `allowed_tools` / `disallowed_tools` — 工具允许列表和拒绝列表。
- 工具使用前的钩子点用于自定义成本核算。

与权限模式阶梯结合（第 10 课）。一个没有 `max_budget_usd` 的 `autoMode` 会话是无约束的自主性。Anthropic 明确将自动模式框架化为需要预算控制；分类器与成本正交。

### EU AI 法案、OWASP Agentic Top 10

Microsoft 的 Agent 治理工具包覆盖 OWASP Agentic Top 10 和 EU AI 法案第 14 条（人类监督）的要求。在欧盟的生产中，日志记录和上限强制执行不是可选的。

### 观察到的 $1,200 → $4,800 案例

Microsoft 文档中的真实案例：一个电商 Agent 在添加新工具后月度成本翻了三倍。该工具允许 Agent 在每次会话中轮询订单状态。没有循环检测。没有每工具上限。没有周环比增长警报。修复是每工具上限加上每日增长警报。这是一个模板：每个新工具面都是一个新的潜在循环；每个新工具都需要自己的上限和自己的警报。

## 练习题

1. 运行 `code/main.py`。确认速率限制在轮询循环轨迹上先于迭代上限触发。现在禁用速率限制并测量 Agent 在迭代上限捕获前"花费"了多少。
   *思考并实践此练习*

2. 为浏览器 Agent（第 11 课）设计一套每工具上限。哪个工具需要最紧的上限？哪个工具可以无限制运行而不会有风险？
   *思考并实践此练习*

3. 阅读 Microsoft Agent 治理工具包文档。列出工具包命名的每种上限类型。将每种映射到一个失败模式（失控循环、缓慢泄漏、糟糕的发布、激增）。
   *思考并实践此练习*

4. 为一个现实任务（例如，"在仓库中分类 50 个 issue"）估算一个通宵无人值守运行的价格。将 `max_budget_usd` 设为点估计的 2 倍。论证 2 倍的合理性。
   *思考并实践此练习*

5. Claude Code 的 `max_budget_usd` 在会话总成本上触发。设计一个你会在外部强制的补充速率限制。什么触发切断，重新启用是什么样的？
   *思考并实践此练习*

## 术语速查表

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| 钱包拒绝服务 (Denial of Wallet) | "失控账单" | Agent 循环产生消耗但没有上限停止它 |
| max_tokens | "每请求上限" | 单次补全大小的上限 |
| max_turns | "迭代上限" | 会话中 Agent 循环迭代的上限 |
| max_budget_usd | "金额终止开关" | 会话成本上限；违规时终止 |
| 速率限制 (Velocity Limit) | "速率上限" | 短窗口内的花费限制（例如，50 美元/10 分钟） |
| 分层路由 (Tiered Routing) | "先用小模型" | 便宜模型默认；仅在分类器判定时升级 |
| 提示缓存 (Prompt Caching) | "缓存的系统提示" | 提供商端缓存将重新发送的 Token 成本降至接近零 |
| HITL 检查点 (HITL Checkpoint) | "人类批准门控" | 昂贵操作前需要人类点击 |
