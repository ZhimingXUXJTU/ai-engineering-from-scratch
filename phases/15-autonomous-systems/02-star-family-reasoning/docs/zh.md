# STaR、V-STaR、Quiet-STaR — 自我推理方法

> 最小可能的自我改进循环隐藏在推理过程中。模型生成一条思维链，保留得出正确答案的那些，并在这些数据上微调。这就是 STaR。V-STaR 添加了一个验证器以改善推理时选择。Quiet-STaR 将推理下沉到每个 Token。三者都有效。但都不是魔法——循环保留碰巧得到正确答案的任何捷径。

> **【中文解读】** 最小的自我改进循环隐藏在推理过程中：模型生成思维链，保留正确答案的推理过程，在这些数据上微调。这就是 STaR。V-STaR 添加验证器改善推理时选择。Quiet-STaR 将推理下沉到每个 token。三者都有效，但都不是魔法——循环保留了碰巧得到正确答案的任何捷径。

> **【拓展：STaR → OpenAI o1/o3 的自我改进】** STaR 系列是"自我博弈"训练的核心思路——模型用自己的推理输出来训练自己。OpenAI o1/o3 系列模型背后的强化学习训练就采用了类似思路：生成多个推理路径，选择正确的，用它们来改进模型。这是实现 AI 自我改进闭环的关键技术。

## 问题引入

教模型推理的直接方法是收集人类编写的推理轨迹。这既昂贵又缓慢，还受限于人类愿意编写多少高质量思维链。

STaR（自我推理器，Self-Taught Reasoner，Zelikman 等人，2022）提出了一个问题：如果模型自己编写推理过程并根据已知答案进行评分会怎样？循环如下：

> **【中文解读】** Star 家族推理技术（STaR、Quiet-STaR、ReST、ReST-EM）通过迭代式自我训练提升 LLM 推理能力。核心思想：让模型生成推理轨迹，过滤高质量轨迹，用这些轨迹微调模型，循环迭代。这是 OpenAI o1/o3 系列和 Anthropic Extended Thinking 的技术基础。

1. 采样一条推理轨迹加答案。
2. 如果最终答案正确，保留该轨迹。
3. 在保留的轨迹上微调。
4. 重复。

它有效。GSM8K 和 CommonsenseQA 都在没有新人类标注的情况下得到了改善。但循环有一个内置偏差：任何产生正确答案的推理过程都会被保留，无论推理本身是否合理。V-STaR（Hosseini 等人，2024）通过学习验证器修补了这个问题；Quiet-STaR（Zelikman 等人，2024）将这个思想推广到每个 Token 的内部推理。

## 核心概念

### STaR：在有效的样本上自举

从一个具有较弱推理能力的基础模型开始。在每个训练问题上，采样一条推理轨迹加答案。如果答案与标签匹配，保留（问题、推理、答案）三元组。在保留集上微调模型。重复。

一个关键细节：如果模型永远无法答对某道题，循环就无法在该题上学习。STaR 添加了**合理化 (rationalization)**：对于模型失败的题目，将正确答案作为提示注入，重新提示模型生成导向该答案的推理过程。合理化的推理被加入训练集。

原始论文（Zelikman 等人，2022）的结果：GPT-J 基础模型通过带合理化的重复 STaR 轮次在 GSM8K 上从 5.8% 提升到 10.7%——大约 5 个百分点的绝对提升。在 CommonsenseQA 上，STaR 训练的 GPT-J 6B 达到 72.5%，可与在人工标注推理上微调的 GPT-3 175B（约 73%）媲美——后者是一个大约大 30 倍的模型。

### V-STaR：用 DPO 训练验证器

STaR 丢弃了不正确的推理。Hosseini 等人（2024）观察到这些也是数据：每一对（推理，"这是否正确"）都可以用来训练验证器。他们在正确和错误解决方案上使用直接偏好优化 (Direct Preference Optimization, DPO) 构建排序器。在推理时，采样 N 条推理并选择验证器排名最高的。

报告的增益：在 GSM8K 和 MATH 上，相比之前的自我改进基线提升 +4 到 +17 个百分点，大部分增益来自使用验证器进行推理时选择而非额外的生成器微调。

### Quiet-STaR：每个 Token 的内部推理

Zelikman 等人（2024）提出：如果模型学会在每个 Token 位置生成一个简短的内部推理，而不仅仅是在问题和答案之间会怎样？Quiet-STaR 训练模型在每个预测 Token 之前发出一个隐藏的"思考"，然后通过学习的权重将包含思考的预测与基线预测混合。

结果：Mistral 7B 在 GSM8K 上的零样本改进从 5.9% 提升到 10.9%，在 CommonsenseQA 上从 36.3% 提升到 47.2%，无需任务特定的微调。模型学会了"何时思考"——困难的 Token 获得更长的内部推理；简单的几乎不需要。

### 为什么三者共享一个安全隐患

三种方法都使用最终答案作为梯度信号。一条通过有缺陷推理得到正确答案的推理——利用捷径、猜测或使用不可泛化的模式——会得到正向强化。在分布内问题上捷径有效。在分布外 (OOD) 问题上它会静默崩溃。

V-STaR 的验证器通过学习对推理排序来缓解这个问题，但验证器是在相同的标签集上训练的。它可能学会偏好格式良好但错误的推理而非诚实的不确定性。更安全的设计是将 STaR 风格的数据与 (a) 过程监督奖励模型（奖励中间步骤，不仅仅是答案）和 (b) 留出的分布外评估来打破简单捷径相结合。

### 对比

| 方法 | 训练信号 | 推理成本 | 数据浪费 | 已知失败模式 |
|---|---|---|---|---|
| STaR | 保留正确的（推理，答案） | 1x | 丢弃所有不正确推理 | 捷径推理 |
| STaR + 合理化 | 上述 + 正确答案提示的重试 | 1x | 较少 | 合理化的推理可能不自然 |
| V-STaR | STaR + 两类 DPO 验证器 | Nx（N 中选优） | 最少 | 验证器可能强化自信的错误 |
| Quiet-STaR | 每个 Token 的推理 + 混合权重 | 1.5-3x | 最少 | 仍然是答案条件的梯度 |

### 这在 2026 年技术栈中的位置

STaR 已经不新了。但这个模式在 2025-2026 年无处不在。可验证数学问题上的强化学习（DeepSeek-R1、Kimi-k1.5、o1）就是 STaR 的答案条件梯度信号，只是规模更大。过程奖励模型（Lightman 等人，2023；OpenAI 的"让我们逐步验证"）是过程监督的替代方案。AlphaEvolve（第 3 课）是代码版 STaR，用程序评估器替代标签。Darwin Godel Machine（第 4 课）是 Agent 脚手架自身的 STaR。

理解 STaR 能让所有这些豁然开朗。它是最小可行的自我改进循环。

## 术语速查表

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| STaR | "自我推理器" | 在模型生成的、得到正确答案的推理上微调；重复 |
| 合理化 (Rationalization) | "提示重试" | 注入正确答案并重新提示模型为失败的题目生成推理 |
| V-STaR | "验证器 STaR" | 在正确和错误推理上用 DPO 训练验证器，用于推理时选择 |
| Quiet-STaR | "每个 Token 的推理" | 在每个 Token 位置生成隐藏思考；与基线预测混合 |
| 答案条件梯度 (Answer-conditioned Gradient) | "基于结果的信号" | 训练循环奖励最终答案，而非推理步骤 |
| 过程奖励模型 (Process Reward Model) | "步骤级验证器" | 在每步正确性上训练的奖励模型，不是结果——与 STaR 对比 |
| 捷径推理 (Shortcut Rationale) | "正确答案，错误推理" | 通过不可泛化的模式达到标签的推理；STaR 会保留这些 |
