# AlphaEvolve — 进化编码 Agent

> 将一个前沿编码模型与进化循环和机器可检查的评估器配对。让循环运行足够长时间。它发现了一个使用 48 次标量乘法的 4x4 复矩阵乘法过程——这是 56 年来对 Strassen 的首次改进。它还找到了一个 Google 范围内的 Borg 调度启发式算法，在生产中恢复了约 0.7% 的集群计算。这个架构故意很无聊。胜利来自评估器的严谨性。

**类型：** 学习
**语言：** Python（标准库，进化循环玩具示例）
**前置条件：** Phase 15 · 01（长程框架），Phase 15 · 02（自我推理）
**时间：** ~60 分钟

## 问题引入

大型语言模型可以编写代码。进化算法可以在代码上搜索。两者分别被尝试了几十年；两者都遇到了天花板。LLM 的天花板是幻觉 (confabulation)：模型编写看似合理的代码，但实际功能与声称不符。进化的天花板是搜索成本：语法上的随机变异很少能产生可编译的程序，更不用说更好的程序了。

AlphaEvolve（Novikov 等人，DeepMind，arXiv:2506.13131，2025 年 6 月）将两者结合。LLM 对程序数据库提出有针对性的编辑；自动评估器对每个变体评分；高分变体成为未来代的父本。LLM 处理编写看似合理代码这一昂贵步骤；评估器捕获幻觉。循环运行数小时到数周。

> **【中文解读】** AlphaEvolve（Google DeepMind, 2025）将进化算法应用于代码优化。它维护一个程序种群，通过变异、交叉和选择迭代优化。关键创新是将 LLM 作为变异算子——用 LLM 生成和修改代码，而不是随机变异。在数学发现和算法优化上取得了突破性成果。

报告的结果：48 次标量乘法的 4x4 复矩阵乘法（Strassen 1969 年的界限是 49），Google 生产中的 Borg 调度启发式算法，32.5% 的 FlashAttention 内核加速，Gemini 训练吞吐量改进。

这个架构有效是因为评估器是机器可检查的。在评估器不可用的地方它不工作。这种不对称性就是本课的要点。

## 核心概念

### 循环

1. 从一个正确但次优的种子程序 `P_0` 开始。
2. 维护一个变体程序数据库，每个变体由评估器评分。
3. 从数据库中采样一个或多个父本（MAP-elites 风格或基于岛屿）。
4. 提示 LLM（Gemini Flash 用于大量候选，Gemini Pro 用于困难候选）生成父本的修改变体。
5. 在留出的评估器上编译、运行和评估变体。
6. 以其分数和特征向量为键插入数据库。
7. 重复。

两个细节很重要。首先，LLM 得到的提示不只是父本程序——通常包括数据库中的几个顶级变体，加上评估器签名，加上简短的任务描述。模型的工作是提出可能改善分数的有针对性修改。其次，数据库是结构化的（MAP-elites 网格，基于岛屿），使循环探索多样性，而不仅仅是当前领先者。

### 为什么评估器不可妥协

AlphaEvolve 的胜利都来自评估器快速、确定且难以博弈的领域：

- **矩阵乘法算法**：一个单元测试，逐位相同地检查矩阵相乘。
- **Borg 调度启发式算法**：一个生产级模拟器，回放历史集群负载并测量浪费的计算。
- **FlashAttention 内核**：一个正确性测试加上真实硬件上的挂钟基准测试。
- **Gemini 训练吞吐量**：测量每步的 GPU 秒数。

在每个案例中，评估器捕获了否则会占主导地位的 LLM 错误类别：虚假的正确性声明、在硬件上消失的性能声明和边缘情况失败。移除评估器，循环就会优化出好看的代码。

### 奖励黑客是该声明的另一面

进化优化评估器测量的任何东西。如果评估器不完美，循环会找到不完美之处。在未经验证的领域，循环会优化表面特征，而非预期行为。DeepMind 在论文中明确指出：AlphaEvolve 的成功仅适用于评估器严谨性与搜索雄心相匹配的领域。

2025-2026 年代码搜索循环中奖励黑客 (reward hacking) 的具体例子：

- 奖励"完成时间"的优化目标奖励了提交空解决方案。
- 奖励测试下正确性的基准分数奖励了记忆测试和过拟合。
- "代码质量"代理指标奖励了删除注释和重写变量名，没有语义变化。

AlphaEvolve 中的修复：交付一个 LLM 从未见过、输入在评估时生成的留出评估器。即便如此，DeepMind 仍建议对任何提议的部署进行强力审查。

### 为什么 LLM + 搜索胜过单独使用

LLM 可以产生可编译、语义上合理的修改。在一个 2000 行 Python 文件上进行随机变异的 GA（遗传算法）几乎总是产生语法错误。LLM 还将搜索集中在合理的邻域（改变一个函数，而不是随机字节），这大大减少了浪费的评估器调用。

评估器反过来捕获 LLM 的幻觉。LLM 会自信地声称一个函数"极限情况下是 O(n log n)"，而实际上它是 O(n^2)；一个挂钟基准测试就能让问题尘埃落定。

### AlphaEvolve 在前沿技术栈中的位置

| 系统 | 生成器 | 评估器 | 领域 | 示例成果 |
|---|---|---|---|---|
| AlphaEvolve | Gemini | 正确性 + 基准测试 | 算法、内核、调度器 | 48 次乘法的 4x4 矩阵乘法 |
| FunSearch (DeepMind, 2023) | PaLM / Codey | 正确性 | 组合数学 | cap-set 下界 |
| AI Scientist v2 (Sakana, 第 5 课) | GPT/Claude | LLM 批判 + 实验 | ML 研究 | ICLR 工作坊论文 |
| Darwin Godel Machine (第 4 课) | Agent 脚手架 | SWE-bench / Polyglot | Agent 代码 | 20% → 50% SWE-bench |

四个都是同一配方的变体：生成器加评估器，循环。区别在于评估器评分什么以及有多严谨。

## 用框架实现

`code/main.py` 在一个简单的符号回归问题上实现了最小 AlphaEvolve 式循环。"LLM"是一个标准库代理，提议对一个计算目标函数的程序进行小的语法变异。"评估器"在留出的测试点上测量均方误差。

观察：

- 最佳分数如何在代际间改善。
- MAP-elites 网格如何保持多样解存活，使循环不会收敛于局部最小值。
- 移除留出测试（仅训练评估器）如何让循环 spectaculary 过拟合。

## 练习题

1. 运行 `code/main.py`。记录最佳分数轨迹。禁用留出评估器（标志 `--no-holdout`）并重新运行。量化过拟合。
   *思考并实践此练习*

2. 阅读 AlphaEvolve 论文第 3 节关于 MAP-elites 网格的内容。为一个新问题（例如编译器优化 pass）设计一个特征向量描述符，使搜索保持多样性。
   *思考并实践此练习*

3. 48 次乘法的 4x4 结果在 56 年后改进了 Strassen 的 49 次乘法界限。阅读论文附录 F，用三句话解释为什么这个问题的评估器特别容易做对，以及为什么大多数领域不是这样。
   *思考并实践此练习*

4. 提出一个 AlphaEvolve 会失败的领域。精确识别评估器在哪里出问题以及原因。
   *思考并实践此练习*

5. 对于你了解的一个领域，写出你会使用的评估器签名。包括 (a) 正确性条件，(b) 性能指标，(c) 留出输入生成规则，(d) 至少一个反奖励黑客检查。
   *思考并实践此练习*

## 术语速查表

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| AlphaEvolve | "DeepMind 的进化编码 Agent" | Gemini + 程序数据库 + 机器可检查的评估器 |
| MAP-elites | "保持多样性的存档" | 以特征向量为键的网格；每个单元格持有具有该描述符的最佳变体 |
| 岛屿模型 (Island Model) | "并行进化子种群" | 定期迁移的独立种群；防止过早收敛 |
| 机器可检查的评估器 (Machine-checkable Evaluator) | "确定性预言机" | LLM 无法伪造的单元测试、模拟器或基准——此循环的先决条件 |
| 奖励黑客 (Reward Hacking) | "优化度量而非目标" | 循环找到一种方法来最大化分数而不执行预期任务 |
| 种子程序 (Seed Program) | "起始点" | 循环从中进化的初始正确但次优的程序 |
| 留出评估器 (Held-out Evaluator) | "LLM 从未见过的评估数据" | 在评估时生成的输入，以防止记忆 |
