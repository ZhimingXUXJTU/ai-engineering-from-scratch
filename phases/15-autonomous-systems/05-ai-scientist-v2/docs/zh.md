# AI Scientist v2 — 工作坊级自主研究

> Sakana 的 AI Scientist v2（Yamada 等人，arXiv:2504.08066）运行完整的研究循环：假设、编码、实验、图表、论文撰写、投稿。它是第一个有生成论文通过 ICLR 2025 工作坊同行评审的系统。独立评估（Beel 等人）发现 42% 的实验因编码错误失败，文献综述经常将已建立的概念标记为新颖。Sakana 自己的文档警告该代码库执行 LLM 编写的代码并推荐 Docker 隔离。这幅图的两面都是重点。

**类型：** 学习
**语言：** Python（标准库，研究循环状态机玩具示例）
**前置条件：** Phase 15 · 03（AlphaEvolve），Phase 15 · 04（DGM）
**时间：** ~60 分钟

## 问题引入

研究是一个开放式任务。与 AlphaEvolve 的算法搜索或 DGM 的基准约束自我修改不同，研究结果没有机器可检查的正确性标准。论文由审稿人评判，而非单元测试。这使得循环更难闭合——但如果闭合则更有价值，因为研究是复利增长的所在。

AI Scientist v1（Sakana，2024）通过从人类编写的模板开始闭合了循环。LLM 在固定脚手架中填充实验。AI Scientist v2（Yamada 等人，2025）通过使用带有视觉语言模型批判循环的 Agent 树搜索移除了模板要求。系统生成想法、实施实验、生成图表、撰写论文，并根据审稿反馈迭代。

> **【中文解读】** AI Scientist v2 (Sakana, 2025) 运行完整的研究循环：假设、编码、实验、图表、论文撰写和提交。它是第一个有生成论文通过 ICLR 2025 工作坊同行评审的系统。但独立评估发现 42% 的实验因编码错误失败，文献综述经常将已建立的概念标记为新颖。两面都是事实。

同行评审结论：一篇 v2 生成的论文被 ICLR 2025 工作坊接受（附有披露）。独立评估结论：系统远不够可靠。两者都是事实。

## 核心概念

### 架构

1. **想法生成。** LLM 基于主题和先前文献提出研究想法。v1 使用模板；v2 在假设空间上使用 Agent 搜索。
2. **新颖性检查。** 文献检索步骤检查想法是否已发表。这是 Beel 等人评估发现错误标注的步骤——已建立的方法频繁被归类为新颖。
3. **实验计划。** Agent 起草实验协议并编写代码。
4. **执行。** 代码在沙箱中运行。失败反馈到重试循环。根据 Beel 等人的测量，42% 的实验在此阶段因编码错误失败。
5. **图表生成。** 视觉语言模型阅读生成的图表并重写以提高清晰度。这是 v2 的关键技术添加。
6. **论文撰写。** LLM 起草论文，与内部审稿人迭代。
7. **可选：投稿。** 论文投稿到学术会议。

### 工作坊接受结果意味着什么

一篇 v2 生成的论文通过了 ICLR 2025 工作坊的同行评审。作者向程序委员会披露了论文的来源。这个接受是一个数据点；它不是声称系统"做研究"的许可证。

重要背景：工作坊论文的门槛低于主会议论文。同行评审有噪声；任何一天都有一小部分投稿被接受。一次成功是概念验证，不是可靠性声明。Nature 2026 论文记录了端到端循环，本身就是由人类研究员共同撰写的；不是"系统写了一篇 Nature 论文"。

### 独立评估发现了什么

Beel 等人（arXiv:2502.14297）进行了外部评估。主要发现：

- **实验失败。** 42% 的实验因编码错误（错误的导入、形状不匹配、未定义变量）而失败。重试循环捕获了一些，但不是全部。
- **新颖性误标。** 文献检索步骤频繁将已建立的概念标记为新颖。这是研究领域的幻觉等效物。
- **呈现质量差距。** 视觉语言图表批判产生了出版级视觉效果，掩盖了底层实验弱点。

最后一个发现对本阶段最重要。一个产生令人信服的输出但没有做令人信服的研究的系统，比明显失败的系统更危险而非更安全。评估必须触及底层声明，不能止步于图表。

### 沙箱逃逸隐患

Sakana 自己的仓库 README 警告：

> 由于本软件的性质，它执行 LLM 生成的代码，我们无法保证安全性。存在危险包、不受控的网络访问和产生非预期进程的风险。使用风险自负，并考虑 Docker 隔离。

这是未经验证领域中自主性的操作形态。LLM 编写代码；代码运行；代码可以做进程被允许做的任何事情。没有硬性限制文件系统、网络和进程操作的沙箱，任何自主导向的研究 Agent 都可能泄露数据、消耗计算或重写自身。

AlphaEvolve 的沙箱故事更容易讲，因为它的评估器是紧凑的。AI Scientist v2 的循环运行开放式的代码，追求开放式的目标。这就是为什么它需要更强的隔离（最低 Docker；推荐 seccomp / gVisor）以及对每个提交在离开系统之前进行人工审查。

### v2 在前沿技术栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知失败 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元测试 + 基准测试 | 受评估器严谨性限制 |
| DGM | Agent 脚手架 | 代码 | SWE-bench | 奖励黑客 |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（弱） | 实验失败、误标、粉饰掩盖弱点 |

v2 在三者中拥有最弱的自动评估器、最广的输出面和到公开产物的最短路径。操作控制（沙箱、审查、披露）完成了大部分安全工作。

## 用框架实现

`code/main.py` 将 v2 循环模拟为状态机：想法 → 新颖性检查 → 实验 → 图表 → 论文撰写 → 评审 → 接受或迭代。每个状态具有从 Beel 等人发现中提取的可配置失败概率。运行 N 个循环的模拟器并计数：

- 有多少想法到达投稿。
- 有多少投稿包含打磨的论文隐藏的关键实验缺陷。
- 重试预算如何在质量和产量之间权衡。

## 产出物

`outputs/skill-ai-scientist-sandbox-review.md` 是研究循环 Agent 产出在离开沙箱之前的双门审查清单。

## 练习题

1. 使用默认参数运行 `code/main.py`。循环运行的多少比例产生"干净"论文？多少比例产生图表批判粉饰过的、有实验缺陷的论文？
   *思考并实践此练习*

2. 默认值已使用 Beel 等人的 42% / 25%。使用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 重新运行，然后使用 `--experiment-failure 0.60 --novelty-mislabel 0.40` 运行。打磨但有缺陷的比例在两次运行之间如何变化？
   *思考并实践此练习*

3. 阅读 Sakana 的 AI Scientist v2 仓库 README 中关于沙箱要求的内容。说明你会为多天自主运行添加的两个额外限制（除了 Docker）。
   *思考并实践此练习*

4. 阅读 Beel 等人第 4 节关于呈现质量差距的内容。设计一个额外的评估器来捕获看起来打磨过但实验有缺陷的论文。
   *思考并实践此练习*

5. 为研究 Agent 输出提出一个比"博士读每篇论文"更可扩展的人工审查协议。识别瓶颈并围绕它设计。
   *思考并实践此练习*

## 术语速查表

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| AI Scientist v1 | "Sakana 的模板化研究 Agent" | 在固定脚手架中填充实验 |
| AI Scientist v2 | "无模板研究 Agent" | 带 VLM 图表批判的 Agent 树搜索 |
| Agent 树搜索 (Agentic Tree Search) | "分支研究 Agent" | 并行展开多个实验计划；由内部批判器修剪 |
| 视觉语言批判 (Vision-language Critique) | "VLM 对图表的打磨" | 多模态模型阅读图表并重写以提高清晰度 |
| 文献检索 (Literature Retrieval) | "新颖性检查" | 搜索先前工作以确认想法新颖性——已记录会误标 |
| 粉饰掩盖 (Polish Masking) | "好看的论文，破碎的研究" | 呈现质量超过实验质量；隐藏弱点 |
| 沙箱逃逸 (Sandbox Escape) | "LLM 代码突破限制" | Agent 执行的代码做了循环设计者不打算做的事 |
