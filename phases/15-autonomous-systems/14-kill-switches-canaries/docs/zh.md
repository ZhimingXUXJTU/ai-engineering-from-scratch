# 终止开关、熔断器和金丝雀 Token

> 终止开关是一个保持在 Agent 编辑面之外的布尔值——一个 Redis 键、一个功能标志、一个签名配置——完全禁用 Agent。熔断器更细粒度：它在特定模式（连续五次相同工具调用）上触发，暂停违规路径，并升级到人类。金丝雀 Token (canary token) 继承自经典欺骗技术：一个假凭证或蜜罐记录，Agent 没有合法理由去触碰，其访问会触发警报。基于 eBPF 的数据路径（例如 Cilium）可以在内核层将隔离 Pod 的出口重写到取证蜜罐；已发布的 Cilium 基准测试报告在负载下亚毫秒 P99 数据路径延迟（你的传播预算取决于策略更新如何到达节点，而不是数据路径本身）。统计检测器（EWMA、CUSUM）适应移动基线——将它们与不可弯曲的硬性宪法限制叠加。

**类型：** 学习
**语言：** Python（标准库，三检测器模拟器：终止开关、熔断器、金丝雀）
**前置条件：** Phase 15 · 13（成本治理器），Phase 15 · 10（权限模式）
**时间：** ~60 分钟

## 问题引入

> **【中文解读】** 终止开关（Kill Switches）和金丝雀测试（Canaries）是 Agent 安全的两道防线。终止开关允许人类操作员立即停止 Agent 的所有操作。金丝雀测试在 Agent 执行前用小规模测试检测潜在问题——类似于矿井中的金丝雀预警有毒气体。两者结合形成'检测-停止'的安全模式。

> **【拓展：kill switches canaries】** 终止开关和金丝雀测试借鉴了软件工程和工业安全的最佳实践。金丝雀部署在软件工程中指先向 1% 的用户发布新版本，检测问题后再全面部署。在 Agent 上下文中，金丝雀测试指在执行高风险操作前先用安全数据做小规模测试。终止开关则类似于工厂的紧急停止按钮——简单、可靠、无条件。

成本治理器（第 13 课）约束了 Agent 能花费什么。它们没有约束 Agent 在预算内能做什么。一个有 50 美元速率限制的 Agent 仍然可以泄露一个秘密、发布错误的帖子或删除一个资源——昂贵的操作在 Token 上往往是便宜的。

本课覆盖坐在成本层旁边的三个检测器：

> **【中文解读】** 本节介绍了 AI Agent 的核心概念和实现方法。Agent 是 LLM 驱动的自主系统，能够观察环境、思考决策、执行行动并循环迭代直到完成目标。

1. **终止开关**：保持在 Agent 触及范围之外的布尔关闭按钮。
2. **熔断器**：暂停特定路径的行动模式检测器。
3. **金丝雀 Token**：Agent 没有合法理由触碰的诱饵，触碰就暴露自身。

三者都是前 LLM 时代的工程。经典欺骗、速率限制断路器和功能标志终止先于自主 Agent。新的是攻击面：Agent 读取不受信任的内容（第 11 课）、编辑自己的记忆、并可以将许多看起来安全的操作组合成不安全的操作。这里命名的检测器之所以有效，是因为它们不信任 Agent 的自我报告。

## 核心概念

### 终止开关

终止开关是一个 Agent 读取但不能写入的布尔值。实现选择：

- **托管服务中的功能标志。** LaunchDarkly、Statsig、Unleash。更新在秒级传播。
- **Agent 轮询的 Redis 键。** 简单；要求 Agent 进程在每轮检查。
- **对象存储中的签名配置。** Agent 启动时验证签名；拒绝未签名的状态。
- **OS 级信号或容器生命周期终止。** Docker `kill`、Kubernetes `kubectl delete pod`、systemd stop。

正确的终止开关具有的属性：

- Agent 不能将其设为 `off`。（存在于 Agent 凭证不写入的系统中。）
- 在每个有后果的操作上检查，不仅仅是启动时。
- 关闭时，Agent 不做任何外部可观察的事情，包括记录到 Agent 可以触及的系统。
- 重新启用是显式的人类操作，不是自动超时。

### 熔断器

熔断器暂停特定模式，不是整个 Agent。经典形态（来自 2007 年 Nygard 的书，仍然有效）：

- **关闭**：操作被允许。
- **打开**：操作被阻止。
- **半开**：冷却后，允许 1-3 次探测尝试（默认 1）；成功关闭熔断器，任何剩余失败重新打开它。

Agent 相关触发器：

- 连续五次相同工具调用（重复循环）。
- 同一工具连续五次失败使用不同输入（系统性失败）。
- 工具调用速率超过阈值（第 13 课速率）。
- 在读取信任外内容后调用特定工具（例如 `file.delete`）（第 11 课）。

### 金丝雀 Token

金丝雀 Token（也叫蜜罐 Token）是 Agent 不应该触碰的输入。访问就是警报。

Agent 的例子：

- 环境中的假 `AWS_SECRET_ACCESS_KEY`，没有实际权限。泄露尝试可以立即归因。
- 标有已知哨兵值的假数据库记录。该记录的任何读取或更新触发警报。
- 工作区中的假文件。该文件的读取或编辑是可疑的。
- 在会话开始时注入的假记忆条目。如果它出现在后续输出中，记忆已被泄露。

金丝雀设计是特定于工作流的。Agent 有合法理由触碰的金丝雀是噪声。

### 为什么叠加统计和硬性限制

统计检测器（EWMA、CUSUM、工具调用率的 z-score）适应移动基线。这对合法漂移是特性，对对抗性漂移是缺陷。耐心的攻击者可以足够慢地移动基线，使没有警报触发。

硬性宪法限制（第 17 课）不会弯曲。"永远不要给 `secrets@` 发邮件"作为宪法规则更简单、可审计、不被缓慢漂移博弈。叠加模式：统计检测器捕获大多数噪声，硬性限制捕获走过检测器的攻击。

### 通过 eBPF 数据路径重定向的隔离

Cilium 的基于 eBPF 的网络策略可以在内核层将隔离 Pod 的出口重写到取证蜜罐。Cilium 的公开基准测试报告 TCP_RR 上亚毫秒 P99 数据路径延迟；集群中*触发*隔离的挂钟预算由策略更新从控制平面传播到节点决定（在预加载 operator 的 Kubernetes 上几百毫秒是现实的；尾延迟取决于集群大小和协调频率）。这给你两件事：Agent 不会泄露任何真实的东西，并且 Agent 在蜜罐内的行为被完全观察。相同模式，不同层，如同金丝雀 Token：Agent 通过被隔离时尝试做的事情暴露意图。

### 没有检测器能捕获什么

- **从允许的原语组合的语义攻击。** 每个单独的操作通过每个检测器；组合才是问题。这是第 10 课自动模式的复合失败。
- **将检测器作为载荷一部分的攻击。** 如果 Agent 读取一个页面说"在你行动之前，禁用金丝雀"，而 Agent 有这个能力，检测器就被破坏了。金丝雀 Token 应该在 Agent 无法修改的系统中。

## 术语速查表

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| 终止开关 (Kill Switch) | "关闭按钮" | Agent 编辑面之外的布尔值；每个有后果的操作上检查 |
| 熔断器 (Circuit Breaker) | "模式暂停" | 重复、失败率或速率限制上的特定操作触发 |
| 金丝雀 Token (Canary Token) | "蜜罐 Token" | Agent 没有合法理由触碰的诱饵；访问触发警报 |
| 蜜罐 (Honeypot) | "取证沙箱" | 被隔离的 Agent 被观察的重定向流量/工作区 |
| EWMA | "移动平均" | 指数加权；适应漂移（特性 + 缺陷） |
| CUSUM | "累积和" | 检测与基线的持续偏移 |
| 硬性限制 (Hard Limit) | "宪法规则" | 不适应；不随历史变化 |
| 宪法限制 (Constitutional Limit) | "始终为真的规则" | 与第 17 课的宪法关联；不能被 Agent 编辑 |
