## 问题引入

10 秒 1080p 视频以 24fps 计算是 240 帧的 1920×1080×3 像素。约 1.5 GB 原始数据每个片段。像素空间扩散不可行。你需要：

1. **时空压缩。** 一个编码视频而非帧的 VAE，将视频压缩为时空 patch 序列。
2. **时间一致性。** 帧之间需要共享内容、光照和物体身份。网络需要建模运动。
3. **计算预算。** 相同模型大小下，视频训练比图像贵 10-100 倍。
4. **条件化。** 文本、图像（首帧）、音频或另一个视频。大多数生产模型接受全部四种。

解决这些的架构是应用于时空 patch 的**扩散 Transformer (DiT)**，在巨大的（提示、描述、视频）数据集上训练。与第 06 课相同的扩散损失。

## 核心概念

![视频扩散：patch 化、DiT、解码](../assets/video-generation.svg)

### Patch 化

用 3D VAE（学习的时空压缩）编码视频。潜在表示形状为 `[T_latent, H_latent, W_latent, C_latent]`。切分为 `[t_p, h_p, w_p]` 大小的 patch。对于 Sora 风格的模型，`t_p = 1`（逐帧 patch）或 `t_p = 2`（每两帧一个 patch）。10 秒 1080p 视频压缩为约 20,000-100,000 个 patch。

### 时空 DiT

Transformer 处理展平的 patch 序列。每个 patch 有一个 3D 位置嵌入（时间 + y + x）。注意力通常分解为：

- **空间注意力**在每个帧的 patch 内。
- **时间注意力**在同一空间位置的帧之间。
- **完整 3D 注意力**贵 16-100 倍；仅在低分辨率或研究中使用。

> **【中文解读】** 视频生成的核心技术栈：(1) 3D VAE 将视频压缩为时空潜在表示；(2) 将潜在表示切分为时空 patch；(3) DiT（Diffusion Transformer）处理 patch 序列，使用 3D 位置编码；(4) 注意力通常分解为空间注意力和时间注意力以降低计算量。这与 Sora 的架构一致。

> **【拓展：Sora 架构与 DiT 在视频中的应用】** Sora 的核心是将 ViT 的 patch 化思想扩展到视频领域——将视频视为"时空 patch 序列"。DiT（Diffusion Transformer）用 Transformer 替代 U-Net 作为去噪网络，在视频生成中表现出更好的扩展性。开源实现如 CogVideoX、HunyuanVideo 和 WAN 2.2 都遵循这一架构。

### 文本条件化

与大型文本编码器的交叉注意力（Sora 用 T5-XXL，CogVideoX-5B 用 T5-XXL）。长提示很重要——Sora 的训练集使用 GPT 生成的密集重标注，平均每个片段 200 个 token。

### 训练

时空潜在表示上的标准扩散损失（ε 或 v 预测）。数据：网络视频 + 约 1 亿精选片段 + 合成文本描述。计算：即使小型研究运行也需要 10,000+ GPU 小时；Sora 级别是 100,000+。

## 动手实现

`code/main.py` 模拟了核心的时空 DiT 思想：将一个小的合成视频 patch 化，添加逐 patch 位置嵌入，用 Transformer 风格的注意力对整个 patch 序列去噪。不依赖 numpy；纯 Python。我们展示了当相邻帧的 patch 共享一个去噪器和位置嵌入时，即使在一维中也会出现时间一致性。

### 步骤 1：将合成 1 维"视频" patch 化

```python
def make_video(T_frames=8, rng=None):
    # "视频"是遵循平滑轨迹的 1 维值序列
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### 步骤 2：每帧位置嵌入

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### 步骤 3：去噪器看到整个序列

不同于对每帧独立去噪，我们的微型网络拼接所有帧值 + 其位置嵌入并联合预测所有帧的噪声。

### 步骤 4：时间一致性测试

训练后，采样一个视频。测量帧间差值。如果模型学到了时间结构，差值保持小于独立采样每帧时的差值。

## 常见陷阱

- **独立逐帧采样 = 闪烁。** 如果你分别对每帧运行图像扩散，输出会闪烁，因为每帧的噪声是独立的。视频扩散通过注意力或共享噪声耦合帧来修复这个问题。
- **朴素 3D 注意力 = OOM。** 10 秒 1080p 潜在表示上的完整 3D 注意力是数千亿次运算。分解为空间 + 时间。
- **数据标注比大小更重要。** Sora 相比先前工作的主要升级是在约 10 倍更详细的描述上训练（GPT-4 重新标注片段）。OpenAI 的技术报告明确说明了这一点。
- **首帧条件化。** 大多数生产模型也接受图像作为第一帧。这是"图像到视频"模式；训练包含这个变体。
- **物理漂移。** 长片段（>10s）累积微妙的不一致。滑动窗口生成 + 关键帧锚定有帮助。

## 生产笔记：视频潜在表示是内存带宽问题

10 秒 1080p 片段以 24 fps 计算是 240 帧 × 1920 × 1080 × 3 ≈ 1.5 GB 原始像素。经过 4 倍视频 VAE 压缩（`2 × 空间 × 2 × 时间`）后，每个请求的潜在表示约 100 MB。将其通过时空 DiT 运行 30 步，批大小为 1，你每步在 HBM 中移动约 3 GB——内存带宽而非 FLOPs 是瓶颈。

三个生产旋钮，都直接来自生产推理文献：

- **DiT 上的 TP。** 文本生成视频模型通常 ≥10B 参数。4 块 H100 上的 TP=4 是标准配置；405B 级模型用 PP=2 × TP=2。每步延迟在 all-reduce 墙之前大致随 TP 线性下降。
- **帧批处理 = 连续批处理。** 生成时，视频在概念上是一批通过注意力链接的帧。连续批处理（飞行中调度）适用：如果模型架构允许滑动窗口生成，在返回帧 `t-1` 的同时开始渲染帧 `t+1`。
- **片段级预填充缓存。** 对于图像到视频，首帧条件化类似于 LLM 的提示预填充：计算一次，在时间解码器传递中复用。这实际上是视频的 KV 缓存。
